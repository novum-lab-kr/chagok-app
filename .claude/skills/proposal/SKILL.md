# 시안 만들기

규칙의 이유는 [작업 방식](../../../docs/WORKING-AGREEMENT.md) 2절, 3절, 6절, 11절. 시각 기준은 [DESIGN-SYSTEM](../../../docs/DESIGN-SYSTEM.md).

## 1. 정책 원문부터

- 시안을 만들기 전에 닿는 규정을 원문으로 확인하고 시안에 출처를 적는다.
  - App Store 심사 지침과 HIG(로그인, 결제, 개인정보, 권한 요청)
  - 회사 브랜드 규정(Apple, 카카오, Google 로그인 버튼 등)
  - 한국 법(약관규제법, 개인정보 보호법, 전자상거래법). `korean-law` 플러그인으로 조문을 연다. [LEGAL-REVIEW](../../../docs/LEGAL-REVIEW.md) 1절 표를 먼저 본다.
- 2차 자료로만 본 내용은 그렇다고 밝힌다. 반려될 수 있는 안은 내지 않는다.
- 안에 외부 자원(로고, 아이콘, 폰트, 디자인 리소스)이 들어가면 그 자원의 **사용권 원문**까지 읽는다. 가이드가 쓰라고 해도 사용권이 앱에 넣기나 공개 저장소에 두기를 막을 수 있다(2026-10-22: HIG는 Apple 디자인 리소스 로고로 버튼을 만들라고 하지만, 그 사용권은 「시안 전용, 소프트웨어에 넣기 금지」). 다운로드나 계약 동의를 부탁하기 전에 확인하고, 핵심 제한을 함께 알린다.

## 2. 안 만들기

- 안은 3개, 하나를 추천으로 표시한다. 지금 화면 구조 안에서 바꾼다. 브랜드와 캐릭터가 걸리면 먼저 묻는다.
- 캡처는 실제 컴포넌트를 렌더해서 만든다. 임시 스토리는 `stories/_proposal/`에 두고 커밋하지 않는다. 그림으로만 그린 안이면 그렇다고 적는다.
- 문구는 사용자 관점으로 쓴다. 가운뎃점으로 낱말을 잇지 않는다.

## 3. 아티팩트

- `artifact-design`, `artifact-capabilities` 스킬을 먼저 불러온다.
- 고르기와 메모를 `db`에 저장한다. 키는 `review/choice-<주제>`(고른 안), `review/note-<주제>-<안>`(메모).
- 원본(템플릿, 생성 스크립트)은 `docs/design/proposals-2026-10/`에 두고 README 표에 한 줄 더한다.
- Artifact 도구를 쓸 수 없는 환경이면 HTML과 캡처 경로를 돌려주고 메인 세션이 발행한다.

## 4. 메모 답하기

- `ArtifactData`로 `review/` 아래를 읽는다. 범위 밖으로 보이는 메모도 모두 반영하거나 반영하지 않는 이유를 적는다.
- 같은 주소로 고쳐 낸다. 몇 판인지와 바뀐 점을 README 줄에 적는다.

## 5. 확정 뒤

- 사용자가 고른 안만 Storybook과 코드에 반영한다. 임시 스토리는 스크래치패드로 옮긴다.
- 화면이 바뀌면 흐름도도 맞춘다(`ship` 스킬).
- 반영된 시안의 원본과 README 줄은 다음 worktree 정리 때 지운다.

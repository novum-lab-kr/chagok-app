# 1.1.0 출시 순서

1.1.0을 언제 어떻게 내보낼지 정한 문서다. 2026-11-01에 처음 쓰고 2026-11-05에 1.0 공개 상태에 맞춰 다시 썼다. 지금 상태 칸은 일을 진행하면서 고친다.

## 지금 상태 (2026-11-05)

- **1.0은 한국 App Store에 공개돼 있다.** 2026-11-03 13:45(UTC)부터다(App Store 조회 API로 2026-11-05 확인, 미국 스토어에는 없음). 빌드 7(`538f7eb`, production)이고 `v1.0.0` 태그가 이 커밋에 붙어 있다(원격에도 있음). 1.0 긴급 수정은 이 태그에서 시작한다. 이 문서에 적었던 「1.0.0은 승인돼도 출시하지 않는다」(2026-11-05)는 이미 공개된 뒤라 지웠다.
- **운영 서버를 쓴 사람은 0명이다.** 2026-11-05 14:39(UTC) 운영 DB 조회: 계정 0, 로그인 기록 0, 목표 0, 사진 0. 다만 1.0을 로그인 없이 기기에서만 쓰는 사람은 서버로 알 수 없다. 아래 「1.0 기기 DB 관문」.
- 1.1.0 작업은 `release/1.1.0`에 모은다(`app.json` `version`은 `1.1.0`). main으로 올리는 PR은 앱 저장소 #30이다.
- **버전 이름을 1.0.1에서 1.1.0으로 바꿨다(2026-11-04 사용자 결정).** 구독, 새 스티커 묶음, 다국어, 이벤트 기록, 함께 목표가 들어가 작은 수정판이 아니어서다. 시험 브랜치 `test/1.0.1-integration`과 지난 PR 제목은 옛 이름 그대로다. 미뤄 둔 일은 1.1.1로 부른다. App Store Connect와 다른 외부 서비스에는 1.0.1로 만든 것이 없다(2026-11-04 확인).
- 1.1.0은 아직 제출하지 않았다고 보고 정리했다(정책 PR #64 본문의 「오늘 심사에 올린다」는 2026-11-06에 「제출 직전에 합친다」로 고침). App Store Connect 제출 기록은 보지 않았다.

## 핵심 원칙

**운영 DB는 1.1.0 main 머지 때가 아니라 1.1.0 제출 직전에 바꾼다.** 심사와 승인 직후 사용은 곧바로 운영 서버를 쓴다. 제출 전에 서버가 준비돼 있으면 승인 순간에 따로 할 일이 없다.

**1.0과 1.1.0이 같은 운영 서버를 쓴다.** 1.0 앱은 서버 2판의 호환 함수(`supabase/migrations/20261105000003_api_v1.sql`)로 동작한다. 서버를 바꿀 때마다 1.0 앱이 계속 되는지 본다. 서버 시험(`__tests__/server/syncServer.contract.test.ts` 등)이 이 길을 붙잡고 있다([서버 2판 계획](superpowers/specs/2026-11-04-server-v2-plan.md) 2절).

## 1.0 기기 DB 관문

1.1.0 빌드는 옛 구조 기기 DB(`goal_members` 표가 없는 DB)를 만나면 목표, 스티커, 기록 표를 지우고 새로 만든다(`src/db/client.ts` `dropLegacy`). 1.0 사용자 0명을 전제로 쓴 코드다. 1.0이 공개돼 있으니 **1.1.0을 제출하기 전에 App Store Connect 앱 분석의 설치 수를 본다.**

- 설치 0: 그대로 낸다.
- 설치가 있음: 지우기를 실제 옮기기(옛 목표와 스티커를 `goals`와 `goal_members`로 나누기)로 먼저 바꾼다. 로그인하지 않은 사람의 기록은 기기에만 있어서 지우면 되살릴 길이 없다.

### 처리방침 판

- **1판은 2026-11-03에 게시와 시행됐다**(novum-web main `chagok/versions.json`). 이미 게시한 판은 고치지 않고 새 판을 낸다.
- **2판은 novum-web PR #64로 낸다.** 이용약관 2판(구독, 무료 목표 5개)과 처리방침 2판(앱 오류 보고와 사용 기록)을 머지하는 날 게시와 시행으로 둔다. 이용자가 0명이라 미리 알릴 대상이 없어서다. 머지하는 날이 2026-11-04가 아니면 `versions.json` 두 줄과 두 판 상단 날짜를 그날로 고친다.
- **PR #63(약관 2판, 12-04 시행)은 #64가 대신하므로 닫는다.** 둘 다 `terms/v2`와 `versions.json`을 새로 만들어 함께 머지하면 충돌한다.
- **2판에 함께 목표가 빠져 있다.** `release/1.1.0`에는 함께 목표가 합쳐져 있다(PR #64 본문은 2026-11-06에 이 상태로 고침). 함께 목표는 1.1.0에 넣는다(2026-11-06 사용자 확정). 초안 `docs/superpowers/specs/friends-goal-policy-draft/`를 고쳐 2판에 합친다. 초안의 처리방침 patch는 v1 경로를 가리켜 v2에 바로 들어가지 않는다.
- **함께 목표 문안에 더할 것(2026-11-06):** 초대 링크를 가진 사람은 로그인 없이 목표 이름, 판 종류와 칸 수, 만든 사람 이름, 인원을 본다(앱과 웹 초대 페이지). 초대 코드 대입을 막으려고 없는 코드를 넣은 접속 주소(IP)를 1시간 남긴다(`20261106000001`). 처리방침의 서버 운영 기록 목적에 「부정 이용 방지」를 넣는다.
- 앱은 동의할 때 `versions.json`에서 시행 중인 판을 읽어 기록하고(`src/policy/manifest.ts`, `app/account/connect.tsx`), 새 판 안내도 그 파일로 정한다(`src/policy/versions.ts` `upcomingChange`). 앱 코드에 고정된 판 번호는 없다.

2. **처음 내는 구독은 앱 버전과 함께 심사받는다.** 1.1.0 버전 페이지의 「앱 내 구입 및 구독」에 새 상품 5개를 모두 골라 넣고 제출한다.

4. **약관과 메타데이터:** 자동 갱신 구독은 앱 안과 스토어에 이용약관과 처리방침 링크가 있어야 한다(Apple 개발자 계약 Schedule 2 제3.8(b)). 구독 조항은 이용약관 2판(novum-web PR #64)에 있다. 2판을 게시한 뒤 스토어 설명 끝이나 EULA 칸에 이용약관 주소를 둔다.
5. **확인:** TestFlight 빌드에서 샌드박스 계정으로 월 구독, 해지 예약, 끝남, 구매 복원을 본다.

## 운영 DB 반영

운영 사용자가 0명이라 2026-11-05 서버를 새 구조(서버 2판)로 처음부터 다시 만들었다. 순서는 [서버 2판 계획](superpowers/specs/2026-11-04-server-v2-plan.md) 7절. 이번이 마지막 리셋이고, 다음부터는 새 마이그레이션 파일로 바꾼다(DEV-SETUP 「운영 DB 바꾸기」).

- 2026-11-05 14:39(UTC) 조회: 운영에 들어간 것은 `20261105000001`~`20261105000005` 다섯 개다. **`20261105000006_together_fixes`와 `20261105000007_sticker_period`는 아직 운영에 없다.** 운영 사용자가 아직 0명이면 리셋 때처럼 넣어도 되지만, 1.0이 공개돼 있으니 새 마이그레이션 방식(백업 뒤 `db push`)으로 넣는다. 서버 함수(`purge-photos` 등)가 운영에 올라가 있는지는 확인하지 않았다.

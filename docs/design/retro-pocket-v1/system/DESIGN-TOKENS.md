# 차곡차곡 · Retro Pocket 디자인 토큰 명세

버전 **1.2.0** · 고정 기준 · 2026-09-21

**값의 기준은 [tokens.json](tokens.json), 사용 규칙은 이 문서다.** 이전 시안·프롬프트·버전별 설명과 충돌하면 이 명세를 우선한다. 생성 이미지에서 색을 다시 추출하거나, 화면마다 ‘비슷한 색’으로 바꾸지 않는다. 현재 공통 컴포넌트와 Storybook은 이 JSON을 직접 참조한다. 제품 화면 통합은 별도 단계다.

## 1. 색상

2026-09-21 사용자가 명시한 여섯 색을 고정한다. 생성 이미지에서 색을 다시 추출하지 않는다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| color.screen | **#AFE1CB** | 모든 화면의 기본 배경 |
| color.lcd | **#C7DE94** | 판·스티커 선택 영역·LCD 필드 |
| color.frame | **#06261C** | 프레임·테두리 |
| color.text / textSecondary | **#06261C** | 모든 앱 글씨. 보조 정보는 색 대신 크기·간격으로 구분 |
| color.primary | **#FD855F** | 저장·다음·시작하기, 선택한 목표 칩 |
| color.onPrimary | **#01241C** | 주요 버튼 글씨 |
| color.secondary | **#FEF1D1** | 뒤로·취소·건너뛰기, 비선택 목표 칩 |
| color.onSecondary | **#01241C** | 보조 버튼 글씨 |
| color.input | **#FEF1D1** | 입력창 |
| color.dialog | **#FEF1D1** | 튜토리얼·확인 다이얼로그 본체 |
| color.onDialog | **#06261C** | 다이얼로그 모든 글씨 |
| color.highlight | **#FEF1D1** | 프레임 상단·좌측의 정해진 얇은 하이라이트 |
| color.shadow | **#06261C** | 픽셀 버튼·다이얼로그의 단단한 그림자 |
| color.stickerInk | **#06261C** | 모든 LCD 스티커 픽셀 |
| color.stickerHole | **transparent** | 얼굴·몸 내부. 놓인 면이 그대로 비쳐야 함 |
| color.selectedTab | **#06261C** | 선택한 필터의 채움 |
| color.onSelectedTab | **#C7DE94** | 선택 필터 글씨 |

### 색을 바꾸지 않는 표면 규칙

- 배경·LCD·버튼·다이얼로그는 **단색, 불투명도 1**. 그라데이션·노이즈·광택·전체 색 오버레이 없음.
- 입체감은 아래의 고정 테두리·하이라이트·그림자만 사용한다. 조명 효과로 바탕색을 바꾸지 않는다.
- 그림자는 blur 0, spread 0, x/y 4px. LCD 패널과 스티커 칸은 그림자 없음.
- 사진은 원래 색을 유지한다. 테마 색으로 착색하지 않는다.
- 테마는 light 하나다. OS 다크 모드가 앱 색상을 자동 반전하지 않는다.
- 예외적인 투명도: 비활성 컨트롤 전체 0.4, 다이얼로그 뒤 스크림 0.48, 진행 막대 트랙 0.2. 다른 곳에서 임의 opacity 금지.

## 2. 도트 프레임 규격

숫자는 휴대폰 논리 픽셀(RN dp / 웹 CSS px)이다. 생성 이미지의 1024px 폭에서 재는 값이 아니다.

| 항목 | 고정값 |
| --- | --- |
| 픽셀 계단 단위 | 패널/다이얼로그 4px, 버튼/입력 3px, 셀 2px |
| 모서리 | 3단계: 패널 12px, 버튼 9px, 셀 6px 절삭 |
| LCD 이중 프레임 | 외곽 4px, mint 띠 4px, 안쪽 선 2px |
| 일반 버튼·입력 테두리 | 2px |
| LCD·다이얼로그 외곽 테두리 | 4px |
| 스티커 칸 테두리 | 1px |
| 부드러운 border-radius | 0 |
| 버튼 상단·좌측 하이라이트 | 2px, color.highlight |
| 버튼·다이얼로그 그림자 | 4px 아래·오른쪽, color.shadow, blur 0 |
| 눌림 이동 | 아래 2px; 그림자 y는 2px로 감소 |

셀 모서리 외곽선의 좌측 상단 기준 경로: `(0,6) → (2,6) → (2,4) → (4,4) → (4,2) → (6,2) → (6,0)`. 패널/버튼은 해당 계단 단위를 적용하며 나머지 모서리는 대칭이다. 안쪽 윤곽은 inset에 따라 절삭 폭을 줄인다. 원호를 흐리게 렌더링한 것을 도트 모서리로 취급하지 않는다. 실제 OS 화면 모서리·카메라 구멍은 변경하지 않는다.

## 3. 버튼 상태

| 상태 | primary / secondary 공통 규칙 |
| --- | --- |
| 기본 | 정해진 배경색, 2px 테두리, 4px hard shadow |
| 눌림 | 배경색 유지, 아래 2px 이동, y 그림자 2px |
| 키보드 포커스 | 바깥 2px color.focus 선, 2px 간격; 레이아웃 이동 없음 |
| 비활성 | 동일 색 조합 전체 opacity 0.4; 터치·햅틱 없음 |
| 저장 중 | 동일 외형, 라벨 ‘저장 중’, 중복 탭 차단 |

최소 높이 48px, 좌우 padding 16px, 일반 터치 영역 최소 44px. primary를 새 빨강·코랄·오렌지로 바꾸지 않는다. secondary는 투명 outline 버튼이 아니라 지정된 아이보리 버튼이다. ‘스티커 떼기’처럼 조용한 부가 동작은 별도의 텍스트 액션으로 처리한다.

## 4. 다이얼로그

- 배경 `color.dialog`, 글씨 `color.onDialog`, 4px 픽셀 프레임, 4px hard shadow.
- 바깥 여백 24px, 최대 폭 360px, 안쪽 여백 20px, 버튼 간격 12px.
- 제목 24/32, 본문 16/24. 버튼도 동일 도트 폰트 16/24.
- 1.3.0 추가 (2026-09-29): 보조 글씨 `caption` 14/20(목록 요약·안내 문장), 배지 `badge` 12/18(`PixelBadge`). 기존 값은 바꾸지 않았다.
- 튜토리얼은 진행 숫자 1개 + 제목 1개 + 한 문장 + 건너뛰기/다음(마지막 시작하기).
- 팝업의 장식을 실제 화면에 자동 확장하지 않는다. 필터에 테두리를 추가하는 식의 전파 금지.
- 일반 화면에 장황한 안내문은 없으며, 오류·삭제 확인 등 필요한 순간의 짧은 설명은 유지한다.

## 5. 글씨: ‘도트 정도’ 대신 실제 폰트 고정

**NeoDunggeunmo / Neo둥근모 v1.601 Regular, weight 400**을 모든 앱 글씨의 기준 파일로 지정한다.

- 파일: [neodgm-1.601.ttf](assets/fonts/neodgm-1.601.ttf)
- SHA-256: `77305267996073aae07bad9313dad2e306a4128e55bfafbed4c41558fee57b4d`
- 적용: 로고 글자·제목·본문·버튼·필터·날짜·숫자·입력값·메모·튜토리얼·오류.
- 제외: OS 상태바·시스템 키보드·사진 선택기 등 앱 외부 시스템 UI.
- 임의 굵게/기울임/외곽선/가로 늘리기/자간 벌리기 금지. **synthetic bold 금지**. 제목 강조는 크기로 한다.
- letterSpacing 0. 글꼴 로딩 전 다른 폰트로 완성 화면을 노출하지 않는다.
- 누락 글리프는 조용히 시스템 폰트로 대체하지 말고 지원 범위 이슈로 기록한다. 사용자의 입력은 삭제하지 않는다.

| 역할 | size / line-height |
| --- | --- |
| 브랜드 | 32 / 40 |
| 화면·다이얼로그 제목 | 24 / 32 |
| 진행 숫자 | 24 / 32 |
| 본문·메모·입력 | 16 / 24 |
| 라벨·필터·버튼·보조 글씨 | 16 / 24 |

14px 이하로 줄여 억지로 맞추지 않는다. 넘치면 줄바꿈·가로 스크롤·화면 스크롤로 해결한다. 앱 글씨는 도트 형태가 고정되지만 OS 텍스트 래스터라이징 차이까지 이미지와 동일하다고 보장하지 않는다. 접근성 글자 확대를 끄지 않는다.

이 폰트는 생성 이미지 속 가상의 글씨와 완전히 같은 폰트라는 뜻이 아니다. 반복 가능한 **실제 기준**으로 지금 고정한 것이다. 이후 폰트를 바꾸려면 버전 변경으로 관리한다.

## 7. 스티커 원본 계약

한 스티커 ID는 하나의 원본 자산만 참조한다. 설정 큰 미리보기·목록·홈 작은 표시·붙인 칸·튜토리얼에 동일 자산을 사용한다. 화면별 생성 금지.

새싹이와 기본 스티커 표시의 시각 기준은 사용자가 지정한 [exec-93ab 원본](../revisions/v6/references/sprout-and-label-source.png)이다. 이 참조는 캐릭터·해당 라벨 영역에 한정하며 상단 바·메인 프레임은 최신 픽셀 규격을 유지한다. v5 설정의 둥근 새싹을 기준으로 삼았던 결정은 대체한다. LCD색으로 뚫린 얼굴을 유지한다. 픽셀 자산은 하나의 정수 좌표 그리드를 사용한다. 현재 공통 새싹 초안은 24×24이며 권장 표시 크기는 24의 정수 배수다. 임의 색 보정·피부색·다른 표정 금지.

공통 새싹 픽셀 자산 초안은 `src/design-system/components.tsx`의 `SproutSticker`에 있다. 모든 크기에 같은 원본을 재사용하며 얼굴은 투명하다. 현재 자산은 24×24 픽셀 그리드로 구현했고 시안과의 최종 형태 승인은 아직 없다. 기존 32×32 제안은 이 구현 초안의 실제 규격을 의미하지 않는다.

## 8. 변경 관리와 적용

1. 이미지 생성 결과는 구성 참고 자료이며 색·폰트·스티커의 원본이 아니다.
2. 실제 시안 제작·구현은 이 JSON과 보관한 폰트, 공통 컴포넌트/자산으로 렌더링한다. 이미지 생성만으로 정확한 값이 고정됐다고 말하지 않는다.
3. 토큰 값 변경은 값/이유/영향 화면을 CHANGELOG에 기록하고 버전을 올린다. ‘좀 더 도트스럽게’ 같은 요청을 색 변경 허가로 해석하지 않는다.
4. 화면별 하드코딩 색, 자동 테마 보정, 폰트 교체, 필터 프레임 추가를 금지한다.
5. 기존 문서와 이미지는 비교 기록으로 보존하지만 기준으로 덮어쓰지 않는다.

`src/design-system/tokens.ts`가 이 JSON을 직접 읽는다. Storybook과 공통 React Native 컴포넌트가 실제 연결되어 있다.

## 9. 검증 체크

- JSON 별칭이 전부 해석되는가?
- 배경/버튼/다이얼로그 RGB가 고정값인가? 사진·OS UI 이외의 새로운 색이 있는가?
- 폰트 파일 해시가 일치하고 합성 bold가 없는가?
- 필터 borderWidth와 containerBorderWidth가 둘 다 0인가?
- 새싹이 모든 표시가 같은 자산 ID를 사용하는가?
- 얼굴 안에 별도 색이 없는가?
- 일반 화면의 상시 가이드와 설정 우측 점이 없는가?
- ‘기본 스티커’ 라벨은 있는가?

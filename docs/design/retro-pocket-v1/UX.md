# Retro Pocket · 화면 흐름과 상태

> 색·프레임·버튼·글씨의 최우선 기준은 [디자인 토큰 명세](system/DESIGN-TOKENS.md)다.

> 필터·새싹이·우측 점 장식은 [v5](revisions/v5/README.md), 프레임·색상·기본 스티커 라벨은 [v4](revisions/v4/README.md), 튜토리얼은 [v3](revisions/v3/README.md)를 우선한다. 앱 내부 글씨는 전부 도트이며 상시 사용법 안내는 첫 실행 튜토리얼로 이동한다. OS 상태바는 기본 형태를 유지한다.

## 기본 흐름

목표 없음 → 새 목표 만들기 → 홈에서 판 확인 → 빈칸 탭 → 기본 스티커 붙임 → 붙인 스티커 탭 → 사진·메모(선택).
홈의 설정 버튼 → 목표 설정 → 기본 스티커 변경 → 저장 → 해당 목표의 홈.
홈의 작은 기본 스티커 표시 → 같은 목표 설정의 스티커 선택 영역으로 이동.

## 새 목표

이름 → 판 종류 → 적립판이면 칸 수 → 기본 스티커 → 내 판 만들기.
이름은 공백만 허용하지 않으며 빈 상태에서는 완료 버튼을 비활성화한다.
15·20·30은 제안 프리셋이다. 직접 입력은 양의 정수를 검사하고 상한은 구현 전에 결정한다.
달력판 선택 시 칸 수는 숨긴다. 그달의 실제 날짜 수로 구성한다.
기본 스티커는 새싹이로 미리 선택하며, ‘바꾸기’로 같은 선택 UI를 연다.
저장 중 중복 제출을 막고 실패 시 입력을 보존한 채 재시도 안내를 표시한다.

## 판과 기록

- 적립판은 다음 빈칸만 붙일 수 있도록 네 모서리로 표시한다. 꽉 찬 판은 그대로 남겨 볼 수 있다.
- 달력판은 현재 실제 날짜의 칸만 새로 붙인다. 과거·미래의 빈칸에는 붙이지 않는다.
- 월 이동은 이번 확장 제안이다. 과거 판의 붙인 스티커와 기록은 열어볼 수 있고, 새로 소급해서 붙이지 않는다.
- 월마다 스티커를 올바르게 필터링해야 한다. 다른 달의 같은 날짜가 섞이지 않도록 한다.
- 붙이기 처리 중 연속 탭으로 중복 생성하지 않는다. 실패 시 빈칸을 유지하고 재시도를 안내한다.
- 기록 표시가 있는 스티커에는 작은 픽셀 메모 표시를 추가한다. 새 통계나 평가 의미를 부여하지 않는다.
- 사진·메모는 모두 선택. 둘 다 비어도 스티커가 정상 유지된다.
- 사진이 없으면 사진 영역에 ‘사진 더하기’ 버튼을 보여준다. 사진 선택을 취소해도 메모는 보존한다.
- 저장 실패 시 화면을 닫지 않고 작성 내용을 유지한다.
- ‘스티커 떼기’는 스티커와 연결 기록이 함께 삭제됨을 확인한다. 취소하면 그대로 유지한다.

## 목표 설정

목표별 기본 스티커 ID를 저장한다. 이미 붙인 각 스티커는 당시 스티커 ID를 유지한다.
홈에 돌아와 빈칸을 누르면 바뀐 기본값이 사용된다.
목표 이름 편집과 기본 스티커 변경을 제공한다.
이미 기록한 판 종류·총 칸 수 변경은 데이터 이동 정책이 정해지지 않았으므로 현재 설계에서는 읽기 전용으로 본다.
원본 설정 이미지의 화살표는 생성 시안의 불일치로 기록하며, 구현 기준은 이 문서를 따른다.

## 빈 상태와 접근성

목표가 없으면 목표 칩과 설정을 숨긴다. LCD에 빈 판 고스트, ‘첫 스티커를 모아볼까요?’와 ‘새 목표 만들기’를 보여준다.
가짜 예제 목표나 스티커를 실제 데이터로 저장하지 않는다.
초기 조회 중 LCD 내부에 짧은 로딩 표시, 실패 시 설명과 재시도 버튼을 제공한다.
스크린리더는 목표 이름과 채움 수, 날짜 또는 칸 번호, 붙이기 가능 여부, 기록 유무를 읽는다.
색뿐 아니라 체크·모서리·문구로 선택 상태를 전달한다.
키보드가 올라오면 폼과 저장 동작이 가려지지 않게 스크롤한다.

## 기존 구현과의 차이 / 향후 작업

이 문서는 설계 확장안이며 코드 반영은 아직 하지 않았다.
현재 Goal 모델에는 기본 스티커 필드가 없으므로 구현 시 DB 마이그레이션과 저장 인터페이스 확장이 필요하다.
적립판 3열과 레트로 픽셀 스타일은 이전 HANDOFF의 5열·종이 스타일을 대체하는 이번 디자인 제안이다.
원래 HANDOFF.md는 과거 인계 기록이므로 이 작업에서 덮어쓰지 않았다.
클라우드 동기화는 기존의 별도 구현 범위를 유지하며, 이 시안에 백업 완료 같은 상태를 표시하지 않는다.

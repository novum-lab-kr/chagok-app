# 워치 계획 2: 워치 앱 본 구현

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apple Watch 앱을 만든다. 손목에서 목표를 골라 붙이고, 붙일 때마다 차곡이 머리 위로 블록이 쌓인다. 폰은 계획 1에서 만든 스냅샷과 요청 처리를 그대로 쓴다.

**Architecture:** 폰 쪽은 로컬 Expo 모듈 `modules/chagok-watch`(WCSession)가 워치 요청을 UserDefaults 큐에 쌓고 스냅샷을 `updateApplicationContext`로 보낸다. TS의 `watchPort()`가 그 모듈을 계획 1의 `WatchPort` 모양으로 감싼다. 워치 쪽은 `@bacons/apple-targets`로 만든 SwiftUI 앱 `targets/watch`다. 판단은 하지 않고, 받은 스냅샷에 아직 처리되지 않은 요청을 겹쳐 그린다(위젯과 같은 원칙). 워치의 순수 로직(`Logic/`)은 Foundation만 써서 맥에서 `swiftc`로 테스트한다.

**Tech Stack:** Expo 57 / RN 0.86, expo-modules-core(Swift), `@bacons/apple-targets` 5.0.0, SwiftUI(watchOS 10+), WatchConnectivity, jest + ts-jest.

**Spec:** [워치 설계](../specs/2026-10-16-watch-growth-design.md), [시험 구현 결과](../specs/2026-10-16-watch-spike-results.md), 시안 14판(`docs/design/proposals-2026-10/watch-growth.template.html`), PRD 4.14.

## Global Constraints

- 한국어 문구, 가운데 점(·) 금지. 화면 문구는 사용자 관점(「지난 칸은 폰에서 고칠 수 있어요」).
- 화면에 「책장」을 쓰지 않는다(「보관함」).
- `package.json`의 `overrides: { "react-dom": "19.2.3" }` 유지. 의존성 설치 뒤 `npm ls react-dom --all`이 19.2.3 하나.
- `app.json`은 손으로 고치고 기존 줄 모양(한 줄 객체)을 지킨다. 도구가 다시 포맷하면 되돌린다.
- 판단(칸 번호, 날짜, 완성, 체험 잠김)은 폰 TS가 한다. Swift에는 「어림으로 그리기」에 필요한 만큼만 둔다.
- 요청 모양: `{id, goalId, kind: add|undo|remove, at, dateKey, slotIndex?, complete?: true}`. id는 UUID. 달력판 remove의 slotIndex = 날짜 - 1.
- 빌드는 `-destination 'generic/platform=iOS Simulator'`(또는 기기)만 준다. `-sdk iphonesimulator`는 워치 타깃을 iOS로 빌드해 실패한다.
- 사용자의 8081 Metro는 건드리지 않는다. 시뮬레이터 확인은 Release 빌드로 한다.
- 커밋은 사용자가 직접 돌려 본 뒤(AGENTS.md). 이 계획의 커밋 단계는 「커밋할 묶음」 표시로만 쓴다.

## Review Focus

1. 워치 요청이 폰에서 처리된 뒤에도 워치에 남아 같은 칸이 두 번 붙어 보이는 경우 → 스냅샷의 `handled` id로 지운다.
2. 자정을 넘긴 뒤 폰을 열지 않은 워치 → `afterMidnight`로 바꿔 그리고, 그날 날짜 키로 요청을 보낸다.
3. 성장 수가 워치에서 줄어 보이는 경우(오늘 칸을 떼고 다시 붙임) → 워치는 마지막으로 보여 준 수 아래로 내리지 않는다.
4. 폰과 처음 연결하기 전, 진행 중인 목표가 없을 때, 체험이 끝난 목표 → 각각 정해진 문구.
5. 모양이 틀린 스냅샷(버전이 다름, JSON 깨짐) → 마지막 정상 스냅샷을 그대로 쓴다.

## Task 4: 폰 네이티브 모듈과 watchPort

- [ ] `modules/chagok-watch/`(`expo-module.config.json`, podspec, `ios/ChagokWatchModule.swift`, `index.ts`).
  - `OnCreate`에서 WCSession 활성화. `didReceiveUserInfo`와 `didReceiveMessage`(reply `{ok: true}`)는 받은 사전을 JSON 문자열로 큐(`UserDefaults.standard`, 키 `chagokWatchRequests`)에 더하고 이벤트 `onRequest`를 보낸다. 큐 접근은 잠금 하나로.
  - `isReady()`: 활성화됨 + 짝지음 + 워치 앱 설치.
  - `readRequests()`: 큐의 JSON 문자열 배열. `ack(ids)`: JSON을 풀어 `id`가 같은 것만 지운다(문자열 포함 검사 금지).
  - `send(json)`: `updateApplicationContext(["json": json])`. 실패하면 오류를 던진다.
- [ ] `src/watch/watchPort.ts`: `requireOptionalNativeModule('ChagokWatch')`. 모듈이 없거나 `isReady()`가 false면 null. `readRequests`는 JSON을 풀고 못 푸는 것은 버린다. `send`는 `JSON.stringify`.
- [ ] RED/GREEN jest `__tests__/watchPort.test.ts`(expo-modules-core를 mock): 모듈 없음 → null, 준비 안 됨 → null, 깨진 JSON은 빠지고 나머지는 객체로, send는 문자열로 넘긴다.
- [ ] `syncWatch.ts`: 모듈의 `onRequest` 구독 → `runner.run()`. 정리 함수에서 해제.

## Task 5: 워치 Logic (Foundation만, swiftc 테스트)

- [ ] `Logic/Snapshot.swift`: `WatchSnapshot`, `WatchDayView`, `WatchGoal`, `WatchBoard`(enum, `type`으로 구분) Codable. `v != 1`이면 디코드 실패로 본다.
- [ ] `Logic/Request.swift`: `WatchRequest`(위 요청 모양, Codable, `[String: Any]`로 바꾸기).
- [ ] `Logic/Overlay.swift`:
  - `dayView(snapshot, todayKey) -> WatchDayView`: 오늘 키가 `afterMidnight.today`면 그쪽.
  - `overlay(day, pending) -> [WatchGoal]`: 처리 안 된 요청을 at 순서로 겹친다. add: 적립판은 첫 빈칸을 placedToday로, 달력판은 그 날을 placed(오늘이면 placedToday). remove: 그 칸/날을 empty. `remaining`을 맞춘다. complete가 붙은 add면 목표를 목록에서 뺀다. 순서는 마지막으로 붙인 목표를 맨 앞으로.
  - `pendingAfter(snapshot, pending) -> [WatchRequest]`: `handled`에 든 것, 2일보다 오래된 것을 뺀다.
- [ ] `Logic/Tap.swift`: `tapTally(goal, index)`, `tapStick(goal)`, `tapDay(goal, day, todayKey)` → `.add(complete: Bool)` / `.confirm` / `.remove(slot)` / `.toast(String)` / `.none`. 문구는 PRD 4.14 그대로. `remaining == 1`이면 `.confirm`. `locked`면 `.toast(lockedCopy)`. 사진이나 메모가 있는 칸이면 지난 칸 문구.
- [ ] `Logic/Growth.swift`: `shownGrowth(snapshot, pending, lastShown) = max(lastShown, snapshot.growth + 처리 안 된 add 수)`. `heads(g) = g % 3`, `bundles(g) = g / 3`, `boxes(g) -> [Int]`(맨 앞 = 지금 채우는 보관함의 묶음 수, 보관함 하나 = 묶음 16). `headColors(recentColors, g)`(최근 블록 색, 모자라면 기본 색 돌려 쓰기).
- [ ] `targets/watch/Tests/LogicTests.swift` + `scripts/test-watch-logic.sh`(swiftc로 Logic과 테스트를 한 실행 파일로). 테스트: 자정 넘김, add/remove 겹치기, complete로 목록에서 빠짐, handled로 지움, 오래된 요청 지움, 마지막 칸 confirm, 지난 칸 토스트, 사진 칸 토스트, 잠긴 목표 토스트, 성장 줄지 않음, 보관함 나누기(0, 2, 3, 48, 49, 100), 머리 위 색.

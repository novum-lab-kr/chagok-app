# 홈 화면 위젯 설계

2026-09-30 · 하위 프로젝트 3/3 · 관련: [PRD 4.1·2](../../PRD.md), [계정·백업 설계](2026-09-30-account-backup-design.md)

> **2026-10-04 갱신:** 모양과 동작이 바뀌었다 — 링 위젯 + 달력 위젯 두 종류, 위젯에서 바로 붙이기, 테두리 없이 꽉 채움, 바탕 민트·아이보리(+유리는 iOS 투명·틴트 모드). 이 문서와 다르면 [PRD 4.10](../../PRD.md)이 우선한다. 스냅샷·데이터 흐름 부분은 그대로 유효하다.

## 목표

사용자가 고른 목표의 진행과 판을 홈 화면에서 보고, 누르면 그 판 상세로 들어간다.
위젯은 **읽기 전용**이다. 평가·재촉 문구("오늘 아직 안 붙였어요" 등)는 넣지 않는다(PRD 2절).

## 결정 (2026-09-30)

| 항목 | 결정 |
| --- | --- |
| 역할 | 보기 + 누르면 판 상세. 위젯에서 붙이기 없음 |
| 플랫폼 | iOS·Android 함께. 데이터 형식은 공통, 화면만 플랫폼별 |
| 표시 목표 | 위젯마다 사용자가 선택(iOS 17+ 위젯 편집, Android 재설정). 선택 없음·삭제·완성이면 가장 최근에 붙인 목표 |
| 크기 | 작은(2×2) = 목록 카드 요약, 중간(4×2) = 판 미니 |
| 로그인 | 무관. 기기 SQLite 기준 |

## 구조

```
기기 SQLite ──(앱이 계산)──▶ WidgetSnapshot (JSON)
                               ├─▶ iOS:     expo-widgets (@expo/ui SwiftUI, App Group)
                               └─▶ Android: react-native-android-widget
```

위젯은 SQLite를 직접 읽지 않는다. iOS 위젯 런타임은 격리돼 있고 hooks·비동기·앱 상태를 쓸 수 없다.
두 플랫폼을 같은 입력으로 맞추기 위해 앱이 스냅샷을 만들어 넘긴다.

**`src/widgets/snapshot.ts`** (순수 함수)

- 목표마다 id, 이름, 기본 스티커 id, 판 종류, 진행 문구, %, 완성 여부.
- 진행 문구는 목록 카드와 같은 `pocketAdapter`에서 만든다. 앱과 위젯의 문구가 어긋나지 않는다.
- 판 미니
  - 달력판: 이번 달 날짜별 상태(붙임 / 지난 빈 칸 / 앞으로). 자정 이후 상태 계산을 위해 날짜 키를 함께 넣는다.
  - 적립판: **다음 빈칸이 들어 있는 한 묶음**의 칸 상태와 전체 `n/nn`. 칸 수 상한이 없으므로 묶음 크기(예: 30)는
    실제 위젯 크기에 렌더해 보고 정한다.
- 선택 가능한 목표 목록(내 목표 탭)과 기본 목표(가장 최근에 붙인 목표).

**전달**

- iOS: `updateSnapshot`/`updateTimeline`. 자정 기준 타임라인 항목을 미리 넣어 "오늘"·"이번 달"이 앱 없이 바뀌게 한다. App Group 필요.
- Android: 스냅샷 JSON을 파일로 두고 위젯 핸들러가 읽어 그린다. 갱신 주기로 날짜 변화를 반영한다.
  (핸들러가 SQLite를 직접 읽을 수 있더라도 공통 형식을 유지한다.)

## 갱신 시점

- 목표·스티커를 바꾸는 쓰기. 계정·백업 설계의 outbox 기록 지점에서 "위젯 갱신 필요" 신호를 보내고 1초 모아서 한 번 처리한다.
- 복원 완료, 로그아웃·계정 삭제 뒤 기기 초기화.
- 자정·월초(위 전달 방식).
- 종료일이 지나 완성되는 판정은 앱을 열 때 `settleExpiredPeriods`가 확정한다. 그 전까지 위젯은 진행 중으로 보일 수 있다(허용).

## 누르면

- 붙이는 곳(링 위젯은 링 안쪽, 달력 위젯은 판 영역) → 앱을 열지 않고 붙인다. 아래 「위젯에서 붙이기」(2026-10-04).
- 그 밖 → `chagok://goal/{id}` → 기존 `/goal/[id]` 판 상세. 목표가 없으면 목록(`/`).
- 빈 상태 위젯 → ~~목록~~ 새 목표 만들기 화면(2026-10-04).

## 위젯에서 붙이기 (2026-10-04)

**원칙: 위젯(Swift)은 "눌렀다"는 사실만 적고, 판단은 모두 앱의 TS 코드가 한다.** 칸 번호·오늘 날짜·백업 outbox·수정 시각 규칙을 Swift에 한 벌 더 만들지 않는다. 둘은 App Group(앱과 위젯이 함께 쓰는 저장 공간) 하나로 잇는다.

```
[위젯 (iOS: Swift App Intent / Android: JS widgetTaskHandler)]
 ① 붙이는 곳을 누름
 ② App Group에 "붙임 요청" 한 줄 추가 {id, goalId, kind: add|undo, at(시각), dateKey(기기 기준 날짜)}
 ④ 위젯 화면만 바로 고쳐 보여 줌 (오늘 칸 채움, % 어림) — 표시용 어림이고 기록이 아니다
                │
[앱 (RN / TS) — 앱을 열 때, 그리고 앞으로 돌아올 때]
 ③ 요청 목록을 읽어 순서대로 처리 → stickerRepository.placeSticker / removeSticker
    (기존 규칙·outbox 그대로. 처리한 요청 id는 지운다)
 ⑤ buildWidgetSnapshot → App Group에 새 스냅샷 → 위젯 새로고침 (TS가 정확한 값으로 다시 맞춘다)
```

- **잇는 곳:** 저장소 안 로컬 Expo 모듈(`modules/`, `npx create-expo-module --local`)에 `readPendingStickers()`, `clearPendingStickers(ids)`, `writeSnapshot(json)`을 둔다. TS는 타입이 있는 함수로만 부른다. Swift는 App Intent와 이 모듈의 저장 공간 읽기·쓰기만 맡는다.
- **Android:** 같은 흐름을 Swift 없이 만든다(`widgetTaskHandler`에서 요청을 쌓는다). 그 안에서 expo-sqlite에 바로 쓸 수 있더라도 두 플랫폼의 흐름을 같게 두기 위해 요청 목록 방식을 쓴다.
- **Swift가 필요 없을 수도 있다:** `expo-widgets` 버튼은 위젯 props만 바꾸고(문서 확인 2026-10-04), `addUserInteractionListener`는 앱이 살아 있을 때만 온다. 위젯이 저장한 값을 앱이 나중에 읽을 수 있다면 Swift 없이 된다 — spike 첫 확인 항목. 어느 쪽이든 ③⑤의 TS 흐름은 같다.
- **같은 요청을 두 번 처리하지 않는다:** 요청마다 id를 두고, 처리한 id는 지운다. 앱이 처리 중에 꺼져도 다음에 다시 읽어 이어 가되, 이미 붙은 칸이면 건너뛴다.
- **되돌리기(undo):** 위젯에서 바로 앞에 붙인 것 하나만. 요청 목록에 아직 남아 있으면 둘을 함께 지우고, 이미 처리됐으면 `removeSticker`로 뗀다.
- **날짜:** 요청에 시각과 **기기 기준 날짜 키**를 함께 적는다. 자정 근처에 붙인 것이 하루 밀리지 않게 날짜 키를 따른다(`toISOString()` 금지 — 작업 방식 5절).

**받아들이는 약점**

- 위젯에 바로 보이는 값은 앱을 열기 전까지 어림이다. 앱을 열면 TS가 정확한 값으로 맞춘다.
- 위젯에서 붙인 기록은 앱을 열어야 DB에 들어가고, 백업도 그때 된다. iOS는 RN 앱을 뒤에서 마음대로 깨울 수 없다.
- 위젯에서는 기본 스티커만 붙는다. 사진·메모는 앱에서 남긴다.

**하지 않는 것:** SQLite 파일을 App Group으로 옮겨 Swift가 DB에 바로 쓰는 방법. 규칙이 두 벌이 되어 어긋나기 쉽다.

**spike에서 확인할 것:** iOS App Intent로 App Group에 쓰기와 위젯 즉시 다시 그리기, `expo-widgets`가 저장한 값을 앱이 읽을 수 있는지, Android `widgetTaskHandler`에서 파일 쓰기, 무료 Apple ID 실기기 설치에서 App Group이 되는지.

## 2026-10-06 본 구현 (iOS)

위 「위젯에서 붙이기」를 이렇게 만들었다. 달라진 점만 적는다.

- **요청 모양 `{id, goalId, kind, at, dateKey}`은 위젯 타임라인 props에 쌓는다.** 로컬 Expo 모듈(`modules/`)은 만들지 않았다. 위젯이 누르면 `requests`에 한 줄을 더하고, 앱은 `getTimeline()`으로 그 목록을 읽는다(`src/widgets/syncCore.ts`). 앱이 처리한 요청은 처리한 id를 설정(`widgetHandledRequests`, 최근 200개)에 남겨 두 번 처리하지 않는다.
- **스티커 id = 요청 id.** 처리 도중 앱이 꺼져 같은 요청을 다시 처리해도 두 번 붙지 않는다.
- **붙인 시각은 늘 누른 시각**(`at`)이고 날짜는 누른 기기의 날짜 키(`dateKey`)다.
- **그리는 방법:** 위젯은 「앱이 준 값 + 처리 안 된 요청」으로 그린다. 요청은 타임라인의 **모든 항목에 합쳐** 보여서 자정을 넘겨도 붙인 것이 유지된다(앱은 지금 + 앞으로 7번의 자정, 8개 항목을 쓴다).
- **되돌리기는 같은 곳을 다시 누르기.** 오늘 붙였고 기록(사진·메모)이 없을 때만. **기록이 있는 스티커는 위젯에서 떼지 않고** 누르면 판 화면이 열린다.
- **마지막 칸은 앱에서 확인한다.** 남은 칸이 1이고 오늘 붙인 것이 없으면 위젯은 붙이지 않고 `chagok://goal/{id}?place=1`로 판 화면을 연다. 화면이 「이 판을 완성할까요?」를 묻는다.
- **목표는 위젯 편집(「바탕」「목표」).** `expo-widgets` 설정 정의를 실제 위젯 코드에 꽂는 설정 플러그인 `plugins/widget-goal`이 만든 Swift를 고쳐서 목표 목록을 위젯 설정에 넣는다. 이번 달 목록엔 달력판만, 적립판 목록엔 적립판만, 목표 하나는 전부. 목표를 고르지 않은 위젯은 가장 최근에 쓴 목표를 따른다.
- **UserDefaults는 `null`을 못 담는다.** props에 `null`이 있으면 `updateTimeline`이 예외를 던져 위젯이 갱신되지 않는다(목표가 0개일 때의 `defaultId`, 종료일 없는 달력판의 `remaining`). `syncCore`가 쓰기 전에 null인 키를 뺀다. 뷰는 `remaining == null`로 읽는다.
- **확인한 것(iPhone 16 Pro 시뮬레이터, 2026-10-06):** 스크린샷은 `docs/design/widgets/`에 있었다(2026-10-18 정리하며 지움, `402913e`에 있다). 위젯 갤러리 세 종류, 편집 「바탕」「목표」와 종류별 목록, 위젯에서 붙이기·떼기와 앱 반영, 같은 종류 위젯 둘의 독립, 마지막 칸, 기록 있는 스티커, 목표 0개 빈 상태, 먹색/아이보리가 홈 화면 라이트·다크와 무관한 것. **자정을 넘기는 시험은 시뮬레이터 시각을 바꿀 수 없어 하지 못했다** — 실기기에서 23:58에 붙이고 앱을 열지 않은 채 0시를 넘겨 확인할 것(요청이 모든 항목에 합쳐지는지, 오늘은 `Ready?`, 앱을 열면 두 스티커가 각각 누른 날짜로 저장).

## 외형

- 앱 팔레트 토큰 값을 그대로 쓴다. `src/design-system/` 값은 바꾸지 않는다.
- 스티커는 SVG(`react-native-svg`)라 위젯에서 그릴 수 없다. 빌드 전 **PNG로 내보내는 스크립트**를 둔다.
- 확인할 것:
  - Neo둥근모를 위젯에 넣을 수 있는지(안 되면 시스템 글꼴)
  - iOS 18 틴트·투명 모드 표시
  - 다크 모드(PRD 6.2 미확정. 앱과 같은 단일 팔레트를 기본으로 둔다)
- **계획 첫 단계는 spike**다. 두 플랫폼에서 글꼴, PNG 스티커, 딥링크, 목표 선택 설정을 최소 위젯으로 확인한 뒤 본 구현한다.
  spike 코드는 버린다.

## 검토와 테스트

- `snapshot.ts` jest: 달력판 월말·월초·자정 경계(로컬 날짜 키), 종료일, 큰 적립판 묶음 경계, 목표 없음, 선택한 목표 삭제·완성, 목록 카드와 문구 일치.
- Storybook: 같은 스냅샷으로 그리는 **RN 미리보기 스토리**(시안 검토용, 실제 위젯 렌더러 아님). 390·320 검수 기준과 별개로 위젯 크기로 렌더한다.
- 시뮬레이터·에뮬레이터 캡처로 실제 위젯 확인.

## 의존성과 선행 조건

- `expo-widgets`(+`@expo/ui`), `react-native-android-widget`. `overrides` 절차를 따른다.
- 개발 빌드 필요(Expo Go 불가). ~~iOS 실기기와 App Group은 Apple Developer Program(유료)이 필요하다.~~ **2026-09-30 정정:** iOS 위젯은 시뮬레이터에서 계정 없이 개발할 수 있다. `expo-widgets`는 App Group을 `group.<번들 ID>`로 자동 설정한다. 실기기는 무료 Apple ID로 설치할 수 있을 것으로 보지만(7일마다 재설치, Apple 로그인 권한이 들어가면 빌드 불가) 직접 확인하지 않았다 — spike에서 먼저 확인한다. 유료 계정은 TestFlight·심사 제출 때 필요하다. Android는 지금 가능하다.
- 패드: `expo-widgets`는 iPadOS에서도 같은 코드로 동작한다. 패드 지원(`supportsTablet`)을 켜면 함께 따라간다.

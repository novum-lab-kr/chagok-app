# 워치 설계: 붙이기와 차곡이 성장

2026-10-16. 관련: [PRD 2절, 4.10, 11절](../../PRD.md), [홈 화면 위젯 설계](2026-09-30-home-widget-design.md), 시안 [워치 성장 14판](https://claude.ai/artifact/HoajBcJvCpsXtzCEhuHsYa)(템플릿 `docs/design/proposals-2026-10/watch-growth.template.html`)

## 목표

손목에서 목표를 골라 바로 스티커를 붙이고, 붙일 때마다 차곡이 머리 위로 블록이 쌓이는 것을 본다.
목적은 꾸준히 붙이게 돕는 것이다. 게임이 아니다. 줄거나 시들지 않고, 연속일수나 재촉은 없다(PRD 2절).

## 정한 것 (2026-10-15~16, 시안 1~14판)

| 항목 | 결정 |
| --- | --- |
| 플랫폼 | Apple Watch 먼저. Wear OS는 범위 밖 |
| 역할 | 보여 주기와 붙임 요청만. 판단은 폰의 TS 코드가 한다(위젯과 같은 원칙) |
| 성장 단위 | **스티커 하나 = 블록 하나.** 폰, 위젯, 워치 어디서 붙여도 한 개 |
| 떼면 줄어듦 | 블록 수 = 지금 붙어 있는 스티커 수. 떼거나 판을 지우면 모션 없이 줄고, 다시 붙이면 처음과 같은 모션으로 쌓인다(2026-10-17 실기기에서 바꿈. 이전: 최고치 유지) |
| 머리 위 | 블록 0~2개. **셋째 블록이 오면 차곡이가 걸어가 세 개를 한 묶음으로 보관함에 넣는다**(S2) |
| 보관함 | 2단 × 4칸, 칸 하나에 얇은 묶음 둘을 나란히(X1). **보관함 하나 = 묶음 16개 = 스티커 48개** |
| 지난 보관함 | 지금 보관함 뒤로 비스듬히 겹친다. 크라운을 돌리면 맨 앞이 빠져 맨 뒤로 간다(R1) |
| 처음 시작 값 | 워치를 처음 연결하면 지금까지 붙인 스티커 전체가 이미 쌓인 상태 |
| 그사이 쌓인 것 | 워치를 열었을 때 폰과 위젯에서 늘어난 블록은 몰아서 한 번 떨어뜨리고, 늘어난 수를 문구로 알린다 |
| 붙이는 기준 | 위젯과 같다(PRD 4.10). 아래 「붙이기」 |
| 이름 | 「보관함」. 화면에 「책장」은 쓰지 않는다 |

## 화면

시안 14판이 기준이다. 화면은 Apple Watch 46mm(208×248pt)로 그렸고 다른 크기는 비율로 맞춘다.
버튼과 목록 줄은 앱 `PixelButton` 틀(`pixelOutline` 5px 두 단, 잉크 3px, 오른쪽 아래 그림자 2px, 안쪽 밝은 선, 누르면 2px 내려감)을 그대로 쓴다.
뒤로 버튼은 작은 틀(계단 2px)에 두께 4px 픽셀 화살표.

1. **첫 화면.** 위에 차곡이(머리 위 블록 포함), 아래에 목표 목록. 줄마다 기본 스티커와 이름. **오늘 하나라도 붙인 목표는 줄 바탕이 민트**(체크 표시 없음, 스티커는 늘 진하게). 순서는 앱과 같은 마지막으로 붙인 순. 넷째 줄부터 크라운으로 내린다. 차곡이를 누르면 차곡이 화면.
2. **목표 판(적립판).** 제목은 위, 판과 묶음 표시와 [붙이기]는 남은 자리의 세로 가운데. 판은 다음 빈칸이 든 10칸 묶음(앱 `StickerSlot` 모양, 다음 빈칸은 네 귀퉁이 괄호). 붙인 수(`n / nn`)는 쓰지 않는다.
3. **목표 판(달력판, K2).** 앱 칸 모양의 큰 오늘 칸과 「오늘, 10월 16일」을 세로 가운데에. 크라운으로 내리면 이번 달 달력. 달력의 오늘 빈 칸은 네 귀퉁이 괄호(2026-10-16 결정 6), 앞날과 시작 전은 흐리게.
4. **완성 확인.** 「이 판을 완성할까요?」「완성한 뒤에도 칸과 기록은 고칠 수 있어요」 [완성하기] [취소]. 앱과 같은 문구.
5. **차곡이 화면.** 바닥 선 위에 차곡이(왼쪽)와 지금 보관함(오른쪽). 지난 보관함은 뒤로 겹친다. 그 아래 문구 한 줄(평소 「지금 채우는 보관함이에요」 또는 「다 채운 보관함이에요」), 그 아래 마지막으로 붙인 판을 실제 칸 수대로 작게(달력판은 이번 달 모양). 붙인 뒤 넘어온 때는 맨 아래 [건너뛰기], 그 밖에는 크라운 표시.

## 붙이기 (위젯과 같은 기준)

- **적립판:** [붙이기]나 빈칸 아무 데를 누를 때마다 다음 빈칸에 붙는다. 하루에 여러 번 된다. 오늘 붙인 칸을 다시 누르면 뗀다. 지난날 붙인 칸은 떼지 않고 「지난 칸은 폰에서 고칠 수 있어요」를 잠깐 보인다.
- **달력판:** 같은 날에는 하나만. 시작일부터 오늘까지의 빈 날을 누르면 그날에 붙는다. 오늘 칸을 다시 누르면 뗀다. 지난날 붙인 칸은 「지난 날은 폰에서 고칠 수 있어요」.
- **사진이나 메모가 있는 스티커**는 워치에서 떼지 않는다(같은 안내).
- **마지막 칸:** 워치에서 완성 확인을 받는다. 위젯은 확인 창을 띄울 수 없어 앱을 열지만, 워치는 확인 화면을 띄울 수 있다. 종료일이 있는 달력판의 기간 안 마지막 빈 날도 같다. 종료일 없는 달력판은 워치에서 완성되지 않는다(폰의 목표 설정).
- **붙인 뒤 흐름:**
  1. 칸이 차고 톡.
  2. 0.3초 뒤 차곡이 화면으로 넘어간다.
  3. 블록이 위에서 떨어져 머리 위에 쌓인다. 차곡이가 받으며 살짝 눌린다.
  4. 셋째 블록이면 꽂을 칸 바로 아래까지 걸어가 묶음을 넣고 돌아온다. 걷는 시간은 거리 × 10ms, 최소 0.45초. 맨 오른쪽 칸은 화면 끝 안에서 멈춘다.
  5. 판으로 돌아온다. 보관하지 않았으면 1.5초, 보관했으면 0.9초 머문 뒤. 완성이면 「○○ 판을 완성했어요」 뒤 첫 화면으로.
- **[건너뛰기]:** 모션을 멈추고 바로 돌아온다. 결과(블록 수, 보관)는 끝까지 본 것과 같다.
- **모션 줄이기**가 켜져 있으면 떨어지기와 걷기 없이 결과만 보이고 바로 돌아온다.
- 떼면 판에서만 빠진다. 블록과 보관함은 그대로다.

## 구조

```
[폰: RN 앱 (TS)]                                     [워치: watchOS 앱 (SwiftUI)]
 SQLite ─▶ buildWatchSnapshot ──(WatchConnectivity applicationContext)──▶ 스냅샷 저장, 화면 그리기
 applyRequests ◀─ 위젯과 같은 요청 목록 ◀─ 폰 네이티브 수신 ◀─(transferUserInfo)─ 붙임 요청
```

- **원칙은 위젯과 같다.** 워치(Swift)는 「눌렀다」는 사실만 보내고, 칸 번호와 날짜 규칙, 완성, 백업 outbox는 모두 폰의 TS가 정한다. Swift에 규칙을 한 벌 더 만들지 않는다.
- **요청 모양은 위젯과 같다:** `{id, goalId, kind: add|undo|remove, at, dateKey, slotIndex?}`. 오늘 붙인 칸을 다시 누르면 `remove`와 그 칸 번호(달력판은 날짜 - 1)를 보낸다. 워치에서 완성 확인을 받은 요청만 `complete: true`를 더한다. 스티커 id = 요청 id라 두 번 처리해도 두 번 붙지 않는다.
- **전달:**
  - 워치 → 폰은 `transferUserInfo`. 폰이 멀리 있거나 꺼져 있어도 줄을 서서 나중에 도착한다. 폰 쪽 네이티브는 받은 요청을 위젯과 같은 요청 목록에 더하고, 앱이 열릴 때 기존 `applyRequests`가 처리한다.
  - 폰 → 워치는 `updateApplicationContext`. 마지막 스냅샷 하나만 유지한다.
- **워치에 보이는 값은 어림이다.** 워치는 「받은 스냅샷 + 아직 처리되지 않은 요청」으로 그린다(위젯과 같은 방식). 폰 앱이 요청을 처리해 새 스냅샷을 보내면 맞춰진다.
- **성장 수(블록 수):** 폰 TS가 지금 붙어 있는 스티커 전체 수로 센다(2026-10-17, 이전: 저장된 최고치와 비교). 완성한 판의 스티커도 센다. 복원하면 복원된 스티커 수로 다시 시작한다. 워치는 요청을 보낼 때 어림으로 1을 더해 바로 보여 준다.
- **워치 스냅샷:**
  - 성장 수, 마지막으로 붙인 목표, 오늘 날짜 키, 자정 뒤 바꿀 값.
  - 진행 중 목표마다 id, 이름, 기본 스티커, 판 종류.
  - 적립판은 칸마다 상태(지난날 붙임, 오늘 붙임, 빈칸)와 기록 여부.
  - 달력판은 이번 달 날짜별 상태, 시작일, 종료일.
- **블록 색:** 머리 위 블록은 아래부터 민트, 아이보리, 살구(2026-10-16 결정 3, 이전: 그 목표 기본 스티커의 대표색). 스티커 대표색(`stickerColors.generated.ts`)은 차곡이 화면 아래 작은 판의 붙인 칸 색으로만 쓴다.
- **그사이 쌓인 것:** 워치는 마지막으로 보여 준 성장 수를 기억한다. 새 스냅샷의 수가 더 크면 차곡이 화면에서 블록을 한 번만 떨어뜨리고 「블록이 n개 늘었어요」를 보인다. 보관할 묶음이 생겼으면 걸어가 넣는 모션도 한 번만.

## 상태

| 상태 | 표시 |
| --- | --- |
| 목표 있음 | 위 화면 |
| 진행 중 목표 없음 | 졸린 차곡이 + 「폰에서 첫 목표를 만들어 보세요」 |
| 폰과 처음 연결하기 전(스냅샷 없음) | 차곡이 + 「폰에서 차곡차곡을 열어 주세요」 |
| 폰에 아직 전달하지 못한 요청 있음 | 따로 표시하지 않는다(어림으로 그림). 전달은 시스템이 줄 세워 처리 |

## 먼저 확인할 것 (시험 구현, 코드는 버린다)

1. Expo 프리빌드에서 watchOS 타깃을 만들고 유지하는 방법(설정 플러그인 또는 `@bacons/apple-targets` 같은 도구). `prebuild --clean` 뒤에도 남는지.
2. WatchConnectivity를 RN 앱에서 쓰는 방법. 받은 요청을 위젯 요청 목록에 더할 수 있는지, 앱이 꺼져 있을 때 받은 `transferUserInfo`가 다음 실행 때 남아 있는지.
3. watchOS에서 Neo둥근모 글꼴, 위젯용 스티커 PNG, 픽셀 그림(차곡이, 블록, 보관함)을 그리는 성능.
4. 시뮬레이터에서 iPhone과 Watch를 짝지어 위 흐름이 도는지. 실기기는 맨 뒤(작업 방식).

## 검토와 테스트

- jest:
  - `buildWatchSnapshot`: 적립판 묶음 경계, 달력판 월초와 월말, 자정 날짜 키, 기록 있는 칸.
  - 성장 수: 떼면 줄고 다시 붙이면 늚, 복원, 판 삭제.
  - 워치 요청 처리: `complete`, 중복 요청, 지난 칸 거절.
- 워치 화면은 SwiftUI 미리보기와 시뮬레이터 캡처로 본다. 모션 줄이기와 VoiceOver 이름(「산책, 오늘 붙였어요」)도 확인한다.
- Storybook에는 시안 확인용 RN 미리보기만 둔다(실제 워치 렌더러 아님). 흐름도(`Flows/앱 전체`)에 워치 진입점을 더한다.

## PRD 반영 (승인 뒤)

- 4.14 「워치」 절을 새로 쓴다. 기존 절 번호는 바꾸지 않는다.
- 2절의 성장 문장을 「스티커 하나 = 블록 하나, 보관함」으로 고친다.
- 11절 「나중에」의 워치 줄을 지우고 12절에 한 줄을 더한다.

## 범위 밖

- Wear OS, 폰 없이 혼자 도는 워치 앱, 워치에서 목표 만들기와 설정, 사진과 메모, 완성한 판 보기.
- 보관함을 열어 묶음 하나하나를 보는 화면, 보관함 꾸미기.

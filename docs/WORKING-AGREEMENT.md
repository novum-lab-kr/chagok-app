# 작업 방식

이 저장소에서 에이전트가 따를 규칙이다. 지금까지 실제로 효과가 있었던 것만 적었다.

## 1. 결정과 작성을 분리한다

**결정이 필요한 것을 먼저 모아 묻고, 그다음에 쓴다.** 앞선 결정이 뒤의 산출물을 규정하기 때문에
순서를 뒤집으면 두 번 쓰게 된다. 예: 달력판 월 경계 정책이 정해져야 데이터 모델 델타를 쓸 수 있었다.

**임의의 숫자나 동작으로 미확정을 메우지 않는다.** PRD에 `미확정`으로 남기고, 정해지면 날짜
스탬프와 함께 확정 이력에 옮긴다. 테스트 통과나 문서의 baseline 표기를 **사용자 승인으로 해석하지
않는다.**

## 2. 시각 작업은 렌더해서 눈으로 보고 고친다

좌표만 계산하고 결과를 안 보면 거의 틀린다. 이 저장소에서 실제로 세 번 헛돌았다 — 런닝 인물이
진저브레드 쿠키로, 따봉이 얹힌 막대로, 운동화가 슬리퍼로 나왔는데 **렌더해보니 1초 만에 보였다.**

```sh
playwright screenshot --full-page --viewport-size "1000,800" "file://$PWD/preview.html" out.png
```

그다음 이미지를 직접 열어서 본다.

- 큰 크기(180px)와 **실제 사용 크기(56px)를 한 페이지에** 같이 깔아 비교한다
- 변형안은 **3~4개를 한 번에** 만들어 나란히 렌더한다. 하나씩 고치면 왕복만 늘어난다
- `outline:1px dashed`로 경계를 표시해 **아이콘 간 시각 무게**가 고른지 본다
- 잘 나온 것을 기준선으로 삼고 "무엇이 다른가"를 본다

## 3. 선택지는 말로 설명하지 말고 보여준다

"A안은 이렇고 B안은 저렇습니다"보다 **세 개를 나란히 렌더해 아티팩트로 발행**하는 쪽이 훨씬 빨리
결정된다. 홈 구조, 달력 월 경계, 따봉 모양 모두 이 방식으로 정해졌다.

## 4. 타입 체크로는 부족하다

`tsc --noEmit`이 통과해도 런타임에 깨질 수 있다. 화면 코드를 만졌으면 **실제 번들까지 돌린다.**

```sh
npx expo export --platform ios --output-dir /tmp/check && rm -rf /tmp/check
```

## 5. 도메인 로직은 TDD로

`slots.ts`, 리포지토리, 어댑터처럼 UI 없는 계층은 실패하는 테스트부터 쓴다. 특히 **타입으로 못 잡는
경계**를 테스트로 고정한다.

- 칸 번호는 1부터, `slotIndex`는 0부터 (off-by-one)
- 달력 키는 로컬 시간. `toISOString()`은 자정 근처에서 하루를 민다

## 6. 디자인 시스템을 재해석하지 않는다

`src/design-system/`의 팔레트·프레임·토큰은 사용자가 승인한 기준이다. **추가는 하되 기존 값을
바꾸지 않는다.** 도메인과 화면의 데이터 모양이 다르면 어느 한쪽을 비틀지 말고
`src/app-data/pocketAdapter.ts` 같은 **어댑터로 흡수**한다.

새 prop은 **선택(optional)으로** 추가해 기존 Storybook 스토리가 계속 렌더되게 한다.

## 7. 코드 작성 전에 버전 문서를 읽는다

루트 `AGENTS.md` 지시다. Expo 57은 이전 버전과 다르다.
`https://docs.expo.dev/versions/v57.0.0/`를 먼저 확인한다. 실제로 이 습관이
`PRAGMA user_version` 마이그레이션 패턴을 찾아줬다.

## 8. 커밋은 덩어리로 나눈다

설정 / 코드 / 문서·에셋을 섞지 않는다. 문서에 PNG가 수십 장 들어가면 코드 diff가 묻힌다.
커밋 메시지에는 **무엇을 왜 그렇게 했는지**를 적는다 — 특히 우회한 제약과 그 이유.

## 9. 막힌 것은 숨기지 않는다

실패한 명령, 미검증 항목, 추측으로 넘어간 부분을 결과 보고에 그대로 적는다.
"실기기 검수 미수행"처럼 **확인하지 않은 것을 확인한 것처럼 쓰지 않는다.**

## 10. 되돌리면 안 되는 것

- `package.json`의 `overrides: { "react-dom": "19.2.3" }` — 지우면 모든 `npm install`이 ERESOLVE로 실패한다
- `jest-expo`를 쓰지 않는 것 — 같은 react-dom 충돌을 일으킨다. `jest` + `ts-jest`가 맞다
- `src/stickers/catalog.ts`(22종) — 참조하는 코드는 없지만 **마이그레이션 매핑 근거**다. 임의 삭제 금지
- `.omc/` — 세션마다 바뀌는 도구 상태. 커밋하지 않는다

# PRD 추가 화면 구현 계획

2026-09-28 · 기준: [구현 현황](HANDOFF.md) · [제품 요구사항](PRD.md) · [화면 시안](design/retro-pocket-v1/prd-additions-review/README.md) · [추가 공통 컴포넌트](design/retro-pocket-v1/component-additions-review/README.md)

## 범위와 원칙

Storybook의 40개 장면은 화면·다이얼로그·오류 상태의 시안이다. 장면마다 라우트를 만드는 대신 기존 네 라우트를 확장하고, 앱 설정·계정·복원처럼 독립적으로 이동해야 하는 화면만 라우트로 추가한다. 짧은 확인은 기존 `PixelDialog variant="basic"`을 네이티브 `Modal` 안에 놓는다. 앱 최상단 톱니바퀴는 앱 설정, 판 제목 옆 톱니바퀴는 목표 설정으로 연결한다.

구현은 기존 `HomeScreen`·`GoalEditorScreen`·`RecordScreen`·`TutorialScreen`과 디자인 시스템 토큰을 재사용한다. 새 시각 요소는 선택 prop 또는 새 컴포넌트로 더하고, 승인된 팔레트·프레임·토큰 값은 변경하지 않는다. 시안은 방향 확인용이며 전체 화면의 최종 픽셀 승인을 뜻하지 않는다.

## 구현 순서

| 순서 | 작업 묶음 | 연결할 화면과 동작 | 완료 확인 |
| --- | --- | --- | --- |
| 1 | 로컬 판·기록의 데이터 경계 | 적립판의 **모든 빈칸** 배치와 중간 칸 유지, 사진·메모 중 하나라도 있는 스티커 ID 조회, 사진을 앱의 지속 저장 공간에 보관하고 유실을 감지 | 임의의 빈칸 배치·제거 후 칸 번호가 유지되고, 빈 기록에는 표식이 없으며, 앱 재시작 후 사진이 열린다 |
| 2 | 홈·기록 연결 | `HomeScreen`의 `allowAnyEmpty`·`recordedSlots`, B안 모서리 표식, 기존 다음 칸 focus, `RecordScreen`의 프레임 안 사진 추가/우상단 삭제·상시 메모 입력, 기록이 있을 때만 떼기 다이얼로그 | 390/320px 홈·기록과 사진 없음/있음/유실/권한 거부 상태가 시안에 맞고, 저장 실패 시 입력이 남는다 |
| 3 | 목표 삭제·판 완료 | 목표 설정의 삭제 진입과 삭제될 수량 확인, 목표·스티커·기록·사진 정리; 마지막 칸 뒤 판 흐림·큰 중앙 도장·완료 다이얼로그, 닫은 뒤 다시 열기, 적립판 칸 늘리기, 달력판의 그 달 완성 표시 | 삭제 전 수량을 보여주고 성공 후에만 화면을 닫는다. 완료 판의 기존 기록은 열리며, 칸을 늘려도 기록이 유지된다 |
| 4 | 첫 사용·앱 설정 골격·공통 경계 상태 | 기존 스포트라이트 튜토리얼 문구 동기화, 목표 없음, 홈 최상단 톱니바퀴와 앱 설정 기본 화면 연결, 저장 안 한 입력의 Android 뒤로가기 확인, 로딩·짧은 알림, iOS 사진 권한 문구 | 첫 실행/건너뛰기/튜토리얼 다시 보기, 설정 진입, 320px 스크롤·키보드·뒤로가기 흐름을 확인한다 |
| 5 | 계정·백업 기반 | 자체 호스팅 Supabase의 인증·RLS·사진 저장·삭제 계약, 로컬 변경 대기열과 재시도, 서버와 로컬 기록 비교/선택, 복원 교체의 원자성 | 오프라인 기록이 유지되고 재연결 시 삭제까지 반영된다. 복원 충돌에서 선택하지 않은 쪽을 명시적으로 경고한다 |
| 6 | 계정 화면 연결 | 앱 설정의 계정 영역, 로그인 권유/만 14세 확인, Apple·Google 로그인, 백업 상태, 복원 진행/실패, 로그아웃 대기/실패, 계정 삭제, 약관·처리방침·라이선스 | '나중에'로 로컬 사용이 가능하고, 로그아웃은 백업 성공 뒤에만 로컬 데이터를 지운다. 계정 삭제는 서버 데이터와 토큰 정리 결과를 확인한다 |

### 각 묶음에서 바꿀 경계

- **1–2:** `app/index.tsx`의 `nextSlotIndex` 일치 조건을 빈칸 검사로 바꾼다. `src/app-data/pocketAdapter.ts`에서 칸 번호·날짜와 기록 표식을 연결한다. `src/repositories/recordRepository.ts`의 현재 `listRecordedStickerIds`는 내용이 빈 `records` 행까지 포함하므로 표시 조건에 맞게 고친다. `app/sticker/[id].tsx`는 image-picker의 임시 URI를 그대로 저장하지 않도록 바꾸고, 사진 유실 시에도 메모를 보여준다.
- **3:** `src/repositories/goalRepository.ts`의 삭제는 DB 외부 사진 파일 정리와 서버 삭제 대기열까지 고려한다. 적립판 칸 늘리기는 기존 데이터가 유지되는 별도 저장 동작으로 만든다. 달력판의 월별 완료 계산에는 선택한 월의 스티커만 사용한다.
- **4:** 확인 UI는 일반 다이얼로그를 공유한다. `HomeScreen`의 `onAppSettings`를 새 앱 설정 화면에 연결한다. 튜토리얼은 현재 `TutorialScreen`의 스포트라이트를 유지하고, 다시 열 때 타깃 좌표가 스크롤에 맞도록 보정한다. 처음 생성한 목표를 홈에서 선택하는 흐름도 이때 확인한다.
- **5–6:** 서버 호출을 화면 컴포넌트에 직접 넣지 않고 인증·백업 서비스와 상태 모델을 둔다. 로컬 저장이 화면의 즉시 성공 기준이며, 계정 연결 후 백업 상태는 앱 설정에서 읽는다. 복원·로그아웃·삭제는 실패 시 교체/삭제를 진행하지 않는 경계 테스트를 먼저 만든다. Apple·Google 버튼은 공식 브랜드 형태를 사용한다.

## 화면 구조

기존 `/`, `/goal/new`, `/goal/[id]`, `/sticker/[id]`를 유지한다. 앱 설정, 계정 연결과 삭제, 복원, 정책/라이선스 열람은 독립 화면으로 추가한다. 판 완료 선택·스티커 떼기·목표 삭제·저장 안 한 입력 확인은 현재 화면 위의 `PixelDialog variant="basic"`으로 처리한다. 칸 늘리기는 기존 `SlotCountPicker`의 입력 경험을 재사용하되 현재 칸 수보다 큰 값만 받는다. 라우트의 구체 이름은 해당 묶음을 시작할 때 정한다.

## 검증 게이트

로직이 있는 묶음은 `slots.ts`·리포지토리·어댑터의 경계 테스트를 먼저 작성한다. 화면 묶음마다 390×844와 320×844, DPR 1에서 Storybook 시안과 실제 렌더를 대조하고 빈/완성/오류 상태를 함께 본다. `npm test`, `npm run test:components`, `npm run typecheck`, `npm run lint`, `npm run build-storybook`, iOS 실제 번들(`npx expo export --platform ios --output-dir /tmp/check`)을 통과시킨다. 사진 권한, 로컬 파일 보존, 햅틱, 모션 감소, 키보드, Android 뒤로가기, 계정 복원과 삭제는 iOS·Android 실기기에서 별도로 확인한다. 실기기 검수 전에는 완료로 표시하지 않는다.

Expo API는 구현 시점에 [SDK 57 문서](https://docs.expo.dev/versions/v57.0.0/)와 설치된 패키지 버전에서 확인한다. 새 의존성을 설치한다면 `package.json`·`package-lock.json`을 먼저 백업하고 설치 후 `react-dom`이 19.2.3 하나인지 검사한다.

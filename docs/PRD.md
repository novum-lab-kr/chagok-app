# 차곡차곡 PRD

버전 1.1 · 2026-09-28 · 현재 합의 및 구현 계획

이 문서는 제품의 목적·사용 흐름·기능 요구사항을 정의한다. 색상, 폰트, 프레임, 공통 컴포넌트의 규격은 별도 [디자인 시스템](DESIGN-SYSTEM.md)에서 관리한다. 이 PRD는 기존 인계 문서와 인터뷰를 정리하고 이후 대화에서 확정된 UX를 반영했다. 미결정 사항을 구현 완료나 사용자 확정으로 취급하지 않는다.

## 1. 제품 목적

사용자가 스스로 정한 목표에 스티커를 직접 붙이고, 원할 때 사진·메모를 남긴다. 시간이 지난 뒤 쌓인 판을 다시 보며 성취감을 느끼는 개인 기록 앱이다. 사용자를 평가하거나 행동의 진위를 판정하지 않는다.

대상은 독서·산책·운동 등 자신이 정한 활동을 가볍게 기록하고 싶은 사용자다. 사용자는 활동을 마친 순간 빠르게 한 칸을 채우고, 기록을 더 남기고 싶은 경우에만 상세 화면으로 이동한다.

## 2. 제품 원칙과 제외 범위

- 스티커를 붙이는 주체는 사용자다. 증명 자료 제출이나 시스템 판정이 필요하지 않다.
- 사진과 메모는 선택이다. 스티커만 붙여도 정상적인 기록이다.
- 붙인 스티커는 다시 뗄 수 있다. 취소 불가나 기록 잠금은 없다.
- 판 자체가 회고다. 별도 회고·아카이브 화면을 만들지 않는다.
- 타인의 판정, AI 자동 평가, 등급, 통계 대시보드, 잔디, 연속일수, 소셜 경쟁은 제외한다.
- 보상 시스템은 보류한다. 다마고치 느낌은 시각적 방향이며 캐릭터 돌보기 게임을 뜻하지 않는다.
  - **고도화 메모 (2026-09-28).** 판 완료 시 보상 기능을 이후 고도화 후보로 검토 중이다. 현재 범위에는 넣지 않는다. 지금의 완성 연출(4.7)을 보상으로 확장하지 않는다.
- iOS와 Android를 대상으로 한다. Storybook은 컴포넌트 검토 도구이며 사용자용 별도 웹 제품을 의미하지 않는다.

## 4. 화면 및 기능 요구사항

### 4.1 홈과 판

**홈 = 목표 목록, 판 = 상세 화면 (2026-09-29 확정).** 목표 칩이 많아지면 이름이 잘리고 판이 밀려서, 홈은 목표 요약 목록으로 하고 목표를 누르면 판 상세 화면을 연다. 목표가 1개여도 목록을 거친다. 시안: Storybook `Screens / Home structure · proposals`.

- 목록 위 한 줄에 `내 목표 n` / `완성한 판 n` 채움 탭(스티커 필터와 같은 모양)을 두고, 같은 줄 오른쪽 끝에 주황 정사각 `+` 새 목표 버튼을 둔다. 작은 화면에서도 스크롤 없이 새 목표에 닿기 위해서다.
- 목록 카드는 스티커, 이름(최대 2줄), 판 종류, 요약 상태, 진행 막대로 구성한다. **모든 판의 카드가 같은 모양이다 (2026-09-29 확정):** `[판 종류 배지] m% 진행중` + 진행 막대, 완성한 판은 `[판 종류 배지] m% M/D 완성` + 진행 막대. 판 종류는 작은 채움 배지로 두고 가운데 점(`·`)은 쓰지 않는다. 종료일 등 기간은 목록에 쓰지 않는다. 이번 달 기준으로 계산하는 종료일 없는 달력판은 오해가 없도록 `이번 달 m% 진행중`(완성한 판은 `9월 m%`)처럼 기준 달을 붙인다. `n칸 / nn칸`은 상세 화면에서만 보여준다.
- **정렬.** 내 목표 탭은 마지막으로 스티커를 붙인 시각이 최근인 목표가 위다. 한 번도 붙이지 않은 목표는 만든 시각으로 비교한다. 스티커를 떼도 이 시각은 바꾸지 않는다. 완성한 판 탭은 완성한 시각이 최근인 순서다.
- 판 상세에는 뒤로가기와 화면 제목(진행 중이면 `내 목표`, 완성한 판이면 `완성한 판` — 목록 탭 이름과 같다, 2026-09-29 확정), 목표 이름, 목표 설정 톱니바퀴, 그 아래 `n / nn [여백] m% 달성중` 한 줄을 둔다. 종료일 없는 달력판은 이번 달 기준으로 `n / nn [여백] 이번 달 m% 달성중`이다. 판의 `기본 스티커` 바로가기와 `차곡차곡 n칸` 누적 줄은 두지 않는다. 기본 스티커는 목표 설정에서 바꾼다.
- 스티커 선택기를 매번 하단에 노출하지 않는다.
- 목표가 하나도 없을 때도 목표를 만드는 행동을 제공한다. **목록 구조를 그대로 두고 탭 아래에 안내 상자 "아직 목표가 없어요 / 오른쪽 위 ＋를 눌러 첫 목표를 만들어요."를 둔다. 만드는 동작은 `+`다 (2026-09-30 확정, Storybook `Screens / Empty goal list`).**
- 일반 화면에 긴 사용 설명을 상시 표시하지 않는다. 사용법은 첫 실행 튜토리얼에서 전달한다.

### 4.2 적립판

- 사용자가 설정한 총 N칸을 채운다. **빈칸이면 사용자가 고른 어느 칸에든 붙일 수 있다 (2026-09-28 확정).** 순서대로 채우도록 강제하지 않는다.
- 빈칸과 이미 붙인 칸을 구분한다. **다음 빈칸 하나만 기존 focus로 강조하지만, 다른 빈칸도 모두 선택 가능하다 (2026-09-28 화면 방향 확정).** 판 아래의 안내 문구 상자는 두지 않는다.
- 진행은 붙어 있는 스티커 수 / 총 칸 수와 그 비율(`m% 달성중`)로 표시한다 (4.1).
- **중간 칸의 스티커를 떼면 그 칸은 빈칸으로 남는다 (2026-09-28 확정).** 다른 스티커는 움직이지 않고, 칸 번호도 그대로다.
- 모든 칸이 차면 판이 완료된다. 완료 뒤의 동작은 4.7을 따른다. 사용자가 고르기 전에 새 판을 자동으로 만들지 않는다.
- ~~완성한 적립판에서 스티커를 하나라도 떼면 다시 진행 중이 된다.~~ **2026-09-29 변경:** 완성한 판은 readonly라 뗄 수 없다 (4.7).

### 4.3 달력판

- 월별 날짜 그리드를 제공한다. 기록이 없는 날은 빈칸으로 표시한다.
- 기존 도메인·인계 규칙은 오늘 칸만 붙이기, 과거 날짜 소급 금지다. 이 PRD에서는 그 규칙을 유지하되 날짜 경계·시간대의 상세 처리는 validation 단계에서 확정한다.
- 이미 붙인 날짜는 기록을 열 수 있다. 같은 날짜에 중복 배치하지 않는다.

**기간과 완성 (2026-09-29 확정).** 한 달을 다 채우는 것은 완성이 아니다. 완성은 기간으로 정한다.

- 시작일은 목표를 만든 날이다. 종료일은 선택이다. 만들 때 고르거나, 나중에 목표 설정에서 추가·변경·삭제한다.
- 시작일은 바꿀 수 없다. 종료일은 마지막으로 스티커를 붙인 날보다 뒤의 날짜로만 바꿀 수 있다. 고를 수 없는 날짜는 비활성으로 보여준다.
- 종료일이 있으면 전체 칸은 시작일부터 종료일까지의 날 수다. **종료일이 지나면 채운 비율과 관계없이 완성**이고, 그 전에 기간 안의 날을 다 채워도 완성이다(마지막 날을 붙일 때 확인, 4.7).
- 종료일이 없으면 진행은 **이번 달 기준**(이번 달에 붙인 날 / 이번 달 날 수, 2026-09-29 확정)이고 `이번 달`을 붙여 표시한다. 달이 바뀌면 0%부터 다시 계산한다. 완성은 목표 설정의 [이 판 완성하기]로 한다. 확인을 받고 완성한다. 완성 뒤 흐름은 다른 판과 같다(연출 → `닫기 / 계속하기` 다이얼로그, 4.7). 계속하기를 고르면 완성을 풀고 진행 중으로 돌아간다. 다이얼로그를 닫으면 readonly다.
- 기간 밖의 날짜는 판에서 비활성으로 그린다. 시작일이 있는 달에서는 이전 달 화살표를, 종료일이 있는 달에서는 다음 달 화살표를 숨긴다. 예: 종료일이 9월 23일이면 9월 24–30일은 비활성, 9월 옆 오른쪽 화살표는 숨긴다.

**월 경계 정책 (2026-09-23 확정)**

달력판은 월이 바뀌면 판이 리셋된다. 제품의 핵심 가치가 "나중에 모아볼 때의 성취감"이므로,
월초에 빈 판만 보이면 그전까지 쌓은 것이 사라진 것처럼 읽힌다. 다음과 같이 처리한다.

- 판은 **월 단위로 보여준다.** ~~한 판을 채우는 완성 경험을 없애지 않는다.~~ **2026-09-29 변경:** 한 달을 채우는 것은 완성이 아니며, 완성은 위의 기간 규칙을 따른다.
- ~~판 위에 누적 총계를 상시 표시한다.~~ **2026-09-29 변경:** 판 상세 상단은 `n / nn · m% 달성중`(기간 없음은 `이번 달 m%`) 한 줄로 바뀌었다 (4.1). 기간 달력판의 n은 **그 목표에 현재 붙어 있는 스티커 수**, 기간 없는 달력판의 n은 이번 달에 붙은 수다. 뗀 스티커는 포함하지 않는다.
- 월 이동은 **이전/다음 버튼과 좌우 스와이프 둘 다** 제공한다.
  - 스와이프는 **달력판에서만** 활성화한다. 적립판은 월 개념이 없으므로 월 이동 제스처를 두지 않는다.
  - 목표 생성일 이전 달과 종료일 이후 달로는 이동하지 않는다 (위 기간 규칙). **기간 없는 달력판은 미래 달로 이동할 수 있다 (2026-09-29 확정).** 미래 날짜에 붙일 수 있는지는 오늘 칸만 붙이는 위 규칙을 따른다.

> 이 절은 요구사항이다. 구현 현황은 [인계 문서](HANDOFF.md) 8절을 따른다.

### 4.4 목표 생성과 설정

- 생성 입력: 목표 이름, 판 종류(`calendar` / `tally`), 적립판의 총 칸 수, 달력판의 종료일(선택, 4.3), 기본 스티커.
- 목표별 기본 스티커를 저장한다. 새로 붙일 때 이 값을 사용한다.
- 설정에서 이름과 기본 스티커를 변경할 수 있다. 변경된 기본값은 이후 배치에 적용하고 이미 붙인 스티커의 종류는 유지하는 것으로 설계한다.
- 선택 영역은 `전체 / 친구 / 모양 / 사물` 필터와 스티커 미리보기로 구성한다.
- 판 종류 카드의 시각 기준은 사용자가 첨부한 [상세 시안](design/retro-pocket-v1/review-set-02/references/board-type-detail-user.png)이며, 기존 `03-new-goal` 이미지보다 우선한다. 달력 요일/빈 칸, 적립판 첫 칸 체크, 주황색 외곽 선택 표시가 기준이다.
- **목표 삭제 (2026-09-28 확정).** 목표 설정에서 삭제한다. 확인 창에 함께 지워질 스티커 수와 기록 수를 보여주고, 확인하면 목표·스티커·기록·사진을 영구 삭제한다. 보관(숨김)이나 휴지통은 두지 않는다. 계정이 연결돼 있으면 서버 백업에서도 지운다 (4.8).
- 판 상세의 제목 옆 톱니바퀴에서 목표 설정을 연다. 항목 순서는 **목표 이름 → 기본 스티커 → 기간(달력판)**이고, 맨 아래에 **[삭제하기] 버튼**을 둔다. 헤더의 휴지통 아이콘은 쓰지 않는다 (2026-09-29 확정). 종료일 없는 달력판은 여기서 [이 판 완성하기]로 완성한다. 완성한 판의 목표 설정은 맨 위에 '완성한 판은 고칠 수 없어요' 안내 상자를 두고, 이름·기본 스티커·판 종류·기간을 읽기 전용으로 보여주며 그 블록 오른쪽에 [완성] 스티커를 붙인다. 동작은 [삭제하기]만 둔다. 새 목표 화면도 이름 → 판 종류 → 기본 스티커 → 종료일(달력판) 순서다. 앱 전체 설정의 진입점과 구분한다 (4.9).
- **총 칸 수는 1 이상이고 상한이 없다 (2026-09-30 변경).** ~~1–100 (2026-09-29).~~ 생성과 칸 늘리기(계속하기) 모두 같다.
- 총 칸 수는 적립판 완료 시 **늘리는 것만** 허용한다 (4.7). 목표 설정 화면에서의 칸 수 변경과 판 종류 변경은 미확정이다.
- 최종 스티커 종수는 미확정이다. 현재 레지스트리나 생성 시안의 항목 수를 제품 확정값으로 삼지 않는다.
- **「참 잘했어요」 도장 계열의 복원 여부는 미확정이다 (2026-09-23).** 현재 스티커 세트(`src/stickers/pocket/catalog.ts`, 6종)에는 이 앱의 출발점이던 칭찬 도장 기호가 없다. 출시 후 반응을 보고 추가 여부를 정한다. 지금 단계에서 도장을 임의로 되살리거나, 반대로 영구 제외로 확정하지 않는다.

### 4.5 스티커와 기록

- 빈칸을 눌러 현재 목표의 기본 스티커를 배치한다. 별도의 붙이기 버튼은 없다.
- **한 판은 같은 스티커로 채워진다 (2026-09-23 확정).** 배치 시점에 종류를 고르는 동작은 두지 않는다.
  이 선택의 결과로 목표 수가 적은 사용자는 전체 스티커 중 일부만 보게 된다. 이는 붙이는 동작을
  한 번의 탭으로 유지하기 위해 감수한 것이며, 배치 중 종류 변경은 후속 재검토 대상이다.
- 배치 시 시각·촉각 피드백을 제공한다. 기기의 모션 감소 설정과 햅틱 사용 가능 여부를 따른다.
- **판 조작 (2026-09-29 확정).** 빈칸을 한 번 누르면 붙인다. 붙인 칸을 한 번 누르면 뗀다(아래 떼기 규칙). 붙인 칸을 **두 번 누르거나 꾹 누르면** 기록 화면을 열어 사진과 메모를 조회·수정한다. 두 번 누르기와 꾹 누르기가 어려운 스크린리더 사용자를 위해 칸에 '기록 열기' 접근성 동작을 따로 둔다.
- 사진만, 메모만, 둘 다, 둘 다 없는 기록을 지원한다. 음성 기록은 범위 밖이다.
- 사진 변경·사진 지우기·메모 편집·스티커 떼기를 제공한다.
- 메모는 기록 화면에서 항상 바로 입력·수정할 수 있다. 별도 '쓰기' 버튼은 두지 않는다. 사진이 없으면 사진 프레임 안에 추가 버튼을, 사진이 있으면 오른쪽 위에 `×` 삭제 버튼을 둔다 (2026-09-28 화면 방향 확정).
- 기록 표식은 B안인 모서리 사각형을 사용한다. 붙인 칸에 사진 또는 비어 있지 않은 메모가 하나라도 있을 때만 표시한다 (2026-09-28 화면 방향 확정).
- **스티커 떼기 (2026-09-28 확정, 2026-09-29 판에서 한 번 누르기로 진입).** 기록(사진·메모)이 없으면 확인 없이 바로 뗀다. 단, 달력판의 지난 날은 다시 붙일 수 없으므로 기록이 없어도 확인을 받는다(2026-09-30). 기록이 있으면 '사진·메모도 함께 사라져요'를 확인받은 뒤 스티커와 기록을 함께 지운다. 저장 성공을 확인하기 전에 완료로 표시하지 않는다.

### 4.6 첫 실행 튜토리얼

**2026-09-29 재작성: 홈 목록·판 상세 구조에 맞춘 5단계.** 예시 화면 위에 기존 타깃 스포트라이트를 쓴다.

1. 목표 만들기: 목록 헤더 오른쪽 `+`를 가리킨다. “＋를 눌러 목표를 만들어요”
2. 스티커 고르기: 새 목표 화면의 기본 스티커를 가리킨다. “목표마다 스티커를 정해요”
3. 빈칸에 톡!: 판 상세의 빈칸을 가리킨다. “어느 빈칸이든 누르면 스티커가 붙어요. 다시 누르면 떼져요”
4. 기록 남기기: 판 상세의 붙인 칸을 가리킨다. “붙인 스티커를 두 번 누르거나 꾹 누르면 사진과 메모를 남길 수 있어요”
5. 완성한 판: 판 상세의 [완성] 스티커를 가리킨다. “판을 다 채우면 완성! 완성한 판은 고칠 수 없고, 붙인 칸을 두 번 누르거나 꾹 누르면 기록을 볼 수 있어요”

각 단계는 짧은 제목, 한 문장, 대상 강조, 다음/건너뛰기 동작으로 구성한다. 완료 또는 건너뛰기 여부를 저장해 매 실행마다 반복하지 않는다. 튜토리얼은 설명만으로 실제 목표나 기록을 임의 생성하지 않는다. 재시작 진입 위치는 후속 결정이다.

### 4.7 판 완료 (2026-09-28 확정)

**완료 순간.** 마지막 칸을 붙이는 순간 짧은 완성 연출과 햅틱을 한 번 준다. 그 뒤에는 판에 '완성' 표시가 남는다. **적립판과 달력판의 완성 연출은 같다 (2026-09-29 확정).** 달력판이 완성되는 조건은 4.3을 따른다.
모션 감소 설정이 켜져 있으면 연출을 생략하고 표시만 보여준다. 포인트·배지 같은 보상은 두지 않는다 (2절 고도화 메모).
**완성 직전 확인 (2026-09-29 확정).** 마지막 칸(달력판은 기간 안의 마지막 빈 날)을 붙일 때 "이 판을 완성할까요? 완성하면 스티커를 붙이거나 떼고, 기록을 고칠 수 없어요"를 확인받는다. 취소하면 붙이지 않는다. 종료일이 지나 완성되는 달력판은 확인 없이 완성되고, 그 판을 처음 열 때 완성 연출과 `닫기 / 계속하기` 다이얼로그를 보여준다.

**완성 표시 (2026-09-29 변경).** ~~판을 흐리게 하고 중앙에 큰 완성 도장을 찍는다 (2026-09-28).~~ 판은 흐리게 하지 않는다. 판 상세 상단 `m% 달성중` 자리에 [완성] 스티커를 붙인다. 그래픽은 **그 판의 기본 스티커 + '완성' 글자 배지**다. 완성한 판은 홈의 완성한 판 탭으로 옮긴다. **완성 모션은 [완성] 스티커가 붙는 '붙이기 모션' 하나다 (2026-09-29 확정).** 판 전체 연출은 따로 두지 않고, 스티커 배치 모션과 같은 결을 쓴다. 모션 감소 설정이면 생략한다. 이 스티커는 4.4절의 스티커 세트 복원 논의와 별개다.

**완성한 판은 readonly (2026-09-29 확정).** 빈칸에 붙일 수 없고, 스티커를 뗄 수 없고, 사진·메모를 고칠 수 없다. 붙인 칸을 한 번 누르면 아무 일도 없고, 두 번 누르거나 꾹 누르면 기록을 읽기 전용으로 연다. 목표 설정은 삭제만 할 수 있다 (4.4). 완성은 되돌리지 않는다.

**완료 뒤 계속하기 (2026-09-29 확정).** ~~새 목표로 시작 / 칸을 늘려 이어 쓰기 / 닫기 (2026-09-28).~~ 완성 연출 뒤 판 위에 `닫기 / 계속하기` 다이얼로그를 띄운다. 적립판, 기간 달력판(마지막 날 채움·종료일 지남), 기간 없는 달력판(수동 완성)이 모두 같은 흐름이다. 버튼 문구는 **`계속하기`**다(2026-09-29 확정, '이어 쓰기'에서 교체). 무엇을 늘리는지는 설명 문장이 말한다. 닫으면 readonly로 보관하고 다이얼로그는 다시 열지 않는다.

| 판 | 계속하기 |
| --- | --- |
| 적립판 | 총 칸 수를 늘린다. 입력은 더할 칸 수이고 기본값은 처음 만든 칸 수다. 사용자가 고칠 수 있다(2026-09-30). 줄이기는 불가하고 상한은 없다. 이미 붙인 스티커와 기록은 그대로다 (4.4) |
| 달력판 (종료일 있음) | 종료일을 늘린다. 지난 날은 붙일 수 없으므로 오늘 이후 날짜만 고른다 |
| 달력판 (종료일 없음) | 완성을 풀고 진행 중으로 돌아간다 |

계속하면 판은 다시 진행 중이 되고 내 목표 탭으로 옮겨진다. 화면은 판 상세에 머문다(2026-09-30). 새 목표는 목록의 `+`로 만든다.

**완성한 판 안내 (2026-09-29 확정).** 판 아래의 상시 안내 문구는 두지 않는다. 대신 첫 실행 튜토리얼의 마지막 단계에서 알린다 (4.6).

### 4.8 계정·백업·복원 (2026-09-28 확정)

기기 교체·재설치 후 복원을 위한 기능이다. **여러 기기 동시 사용은 지원하지 않는다.** 한 계정은 한 기기에서 쓰는 것을 전제로 한 백업·복원이다.
**2026-09-30 보완:** 이후 패드 지원(같은 계정을 여러 기기에서 사용)을 고려해 서버 구조와 변경 기록은 행 단위 병합으로 넓힐 수 있게 만든다. 동기화는 직접 구현(기기 변경 대기열 + 서버 행 단위 반영)이다. 설계: [계정·백업 설계](superpowers/specs/2026-09-30-account-backup-design.md).

**로그인**

- 수단은 **Apple과 Google**이다. iOS는 외부 소셜 로그인을 넣으면 Apple 로그인이 필수다.
- 첫 실행에서 로그인을 권하지만 **'나중에'를 허용한다.** 건너뛰면 이 기기에만 저장되고, 앱 설정에서 언제든 연결한다.
  로그인 필수는 App Store 5.1.1(v)와 오프라인 첫 실행 문제 때문에 택하지 않았다.
- **첫 실행은 로그인 권유가 먼저다 (2026-09-30 확정).** 로그인했고 서버 백업이 있으면 복원하고 튜토리얼을 건너뛴다. 백업이 없거나 '나중에'면 튜토리얼로 간다. 재설치 사용자가 복원 전에 기록을 만들어 충돌 화면을 보지 않게 하기 위해서다.
- 계정을 연결하기 직전 한 화면에서 만 14세 이상 확인과 이용약관 동의를 받고 처리방침을 안내한다 (8.1).
- Apple 로그인에서 이름은 요청하지 않는다. Android에는 Google 로그인만 보인다.
- **만 14세 미만은 계정 연결을 제한한다.** 로그인할 때 만 14세 이상인지 확인하고, 미만이면 로그인 없이 이 기기에서만 쓴다. 서버가 아동의 개인정보를 받지 않으므로 법정대리인 동의 절차를 두지 않는다.

**백업**

- 붙이기·기록·수정·삭제 등 **변경이 있을 때마다 자동으로** 올린다. 오프라인이면 모아 두었다가 연결되면 올린다.
- 삭제도 백업에 반영한다. 뗀 스티커나 지운 목표가 복원 때 되살아나지 않아야 한다.
- 사진은 **리사이즈해서 업로드한다.** 긴 변 1600px, JPEG 80%다 (2026-09-30 확정). 기기에는 원본 복사본이 남는다.
- 백업 상태(마지막 백업 시각, 올리지 못한 변경 유무)를 앱 설정에서 확인할 수 있어야 한다.

**복원**

- 새 기기나 재설치 후 로그인하면 서버 백업을 내려받는다.
- **이 기기에도 기록이 있고 서버에도 백업이 있으면 사용자가 하나를 고른다.** '서버 백업으로 바꾸기'와 '이 기기 기록 유지' 중에서 고르고, 고르지 않은 쪽은 사라진다고 먼저 경고한다.
  '이 기기 기록 유지'를 고르면 서버 백업을 이 기기 기록으로 덮어쓴다.
- 충돌 선택 화면은 목표 생성의 판 종류 선택처럼 두 기록을 선택 상태가 분명한 카드로 보여준다. 질문과 경고는 카드 밖에 두고, 선택한 기록을 쓰는 버튼은 하나만 보여준다 (2026-09-28 화면 방향 확정).

**로그아웃과 계정 삭제**

- 로그아웃하면 올리지 못한 변경을 먼저 모두 올리고, 성공을 확인한 뒤 이 기기의 데이터를 지운다. 올리지 못하면 로그아웃을 멈추고 이유를 알린다.
  **2026-09-30 보완:** 서버가 거부해 보류된 항목만 남았으면, 사라질 변경 수를 경고한 뒤 [그래도 로그아웃]을 허용한다. 보류 항목 때문에 로그아웃이 영원히 막히지 않게 하기 위해서다.
- **계정 삭제는 앱 안에서 할 수 있어야 한다** (App Store 5.1.1(v), Google Play 정책). 서버의 계정·기록·사진을 삭제하고, Apple 로그인 토큰을 폐기한다. Google Play용으로 앱 밖 웹 삭제 요청 경로도 둔다.
- **계정 삭제 뒤 이 기기의 기록은 사용자가 고른다 (2026-09-30 확정).** 삭제 확인 화면의 '이 기기의 기록도 지우기'는 기본 해제다. 남기면 로그인하지 않은 상태로 계속 쓴다.

**서버 (2026-09-28 확정)**

- **자체 호스팅 Supabase**를 Docker로 운영한다. Postgres·Auth·Storage를 쓰고, 네이티브 Apple/Google 로그인은 ID 토큰 방식으로 연결한다.
  빠른 출시를 위해 서버 코드를 최소로 하고, 표준 Postgres라 이후 관리형이나 다른 구성으로 옮길 수 있다.
- **국내 리전의 클라우드**에 둔다. 개인정보 국외 이전을 피한다.
- 사용자별 데이터 분리는 DB 행 단위 권한(RLS)으로 강제한다.
- 서버 DB는 매일 백업하고 **30일 보관한다 (2026-09-30 확정).** 계정을 삭제해도 백업본에 최대 30일 남는다는 점을 처리방침에 적는다. 복구 절차와 모니터링은 미확정이다.

### 4.9 앱 설정

목표 설정(4.4)과 별개로 앱 전체 설정 화면이 필요하다. **앱 최상단의 톱니바퀴**에서 연다 (2026-09-28 화면 방향 확정). 판 제목 옆 톱니바퀴는 목표 설정에만 쓴다. 앱 설정 화면 안쪽의 세부 시각 디자인은 시안 검토 중이다.

- 계정 연결·로그아웃·계정 삭제, 백업 상태 (4.8)
- 이용약관, 개인정보 처리방침, 오픈소스 라이선스(Neo둥근모 SIL OFL 1.1 포함) (8절). 약관·처리방침은 웹 문서를 앱 안 시트로 열고, 라이선스는 앱에 넣는다 (2026-09-30 확정, 8.1)
- 튜토리얼 다시 보기 (진입 위치 미확정 항목, 11절)

### 4.10 홈 화면 위젯 (2026-09-30 확정)

고른 목표의 진행과 판을 홈 화면에서 본다. 설계: [위젯 설계](superpowers/specs/2026-09-30-home-widget-design.md).

- **읽기 전용이다.** 누르면 그 목표의 판 상세를 연다. 위젯에서 붙이기는 사용 뒤 재검토한다.
- iOS와 Android를 함께 만든다.
- 위젯마다 목표를 고른다. 고르지 않았거나 고른 목표가 삭제·완성되면 가장 최근에 붙인 목표를 보여준다.
- 작은 크기는 목록 카드와 같은 요약(스티커, 이름, 판 종류, 진행 문구, 막대), 중간 크기는 판 미니(달력판은 이번 달, 적립판은 다음 빈칸이 든 묶음)다.
- 재촉·평가 문구를 넣지 않는다 (2절). 로그인과 무관하게 기기 기록으로 동작한다.

## 6. 비기능 요구사항

이 절은 기능이 아니라 품질 기준이다. 수치가 확정되지 않은 항목은 미확정으로 표시한다.

### 6.1 접근성

- 스티커를 붙이는 칸, 목표 칩, 팔레트 항목 등 모든 탭 대상은 플랫폼 최소 터치 크기를 만족한다. iOS 44×44pt, Android 48×48dp 기준이다. 달력판은 칸이 작아지기 쉬우므로 시각 크기와 터치 영역을 분리해 확보한다.
- **색만으로 정보를 구분하지 않는다.** 현재 스티커 6종(새싹이·고양이·별·꽃·책·운동화)은 형태가 모두 다르므로 색각 이상에서도 구분된다. 스티커를 추가할 때 이 조건을 유지한다.
- 빈칸·붙은 칸·오늘 칸·다음 칸의 구분은 테두리와 채움 등 색 외의 속성도 함께 사용한다.
- 스크린리더에서 각 칸은 날짜(또는 순번)와 상태를, 스티커는 이름을 읽을 수 있어야 한다. 구체 레이블 문안은 미확정이다.
- 동적 글자 크기 대응 범위는 미확정이다. 픽셀 폰트 특성상 배율에 한계가 있으므로 지원 범위를 정해 명시한다.
- 모션 감소 설정이 켜진 기기에서는 배치 애니메이션을 생략하거나 축소한다.

### 6.2 표시 모드

- 레트로 LCD 방향은 화면 전체가 하나의 고정 팔레트를 쓴다. **다크 모드 대응 방침은 미확정이다.** 시스템 다크 모드를 따를지, 단일 외형을 유지할지 정해야 한다. 정하기 전까지 두 모드를 지원한다고 표기하지 않는다.

### 6.3 성능과 동작

- 판 전환과 월 이동은 조작 직후 즉시 반응해야 한다. 구체 목표 수치는 미확정이다.
- 한 목표가 가질 수 있는 스티커 수의 상한은 정하지 않는다. 다만 누적이 커져도 판 렌더가 느려지지 않아야 하며, 목록 조회는 표시 중인 달로 한정한다.
- **네트워크 없이 모든 기록·조회 기능이 동작한다.** 네트워크가 필요한 것은 로그인, 복원, 백업 전송, 계정 삭제뿐이다. 첫 실행도 '나중에'를 고르면 오프라인에서 쓸 수 있다.
- **최소 지원 논리 폭은 320px이다.** 디자인 시스템 검수도 390px와 320px 두 폭에서 수행한다(인계 문서 1절). 가로 overflow가 없어야 한다.

## 7. 실패와 경계 상태

정상 흐름만 정의하면 구현에서 임의로 처리된다. 아래 상황의 동작을 명시한다.

| 상황 | 요구 동작 |
| --- | --- |
| 사진 권한 거부 | 거부 사실과 설정에서 바꾸는 방법을 알린다. 스티커 붙이기와 메모는 계속 가능해야 한다 |
| 사진 원본 유실 | 기기에서 원본이 삭제돼 `photo_uri`가 깨진 경우, 기록 자체를 잃은 것처럼 보이지 않게 처리한다. 메모는 그대로 보여준다 |
| 저장 실패 | 실패를 알리고 사용자가 한 입력을 잃지 않는다. 성공을 확인하기 전에 완료로 표시하지 않는다 |
| 스티커 떼기 | 기록이 없으면 바로 뗀다. 기록이 있으면 확인 후 함께 지운다 (4.5). 확인 없이 기록까지 지우지 않는다 |
| 목표 없음 | 목표를 만드는 행동을 제공한다 (4.1) |
| 판을 다 채움 | 마지막 칸에서 완성을 확인받고, [완성] 스티커 붙이기 모션 뒤 `닫기 / 계속하기`를 고른다 (4.7). 닫으면 readonly. 자동 보상이나 새 판 자동 생성은 없다 |
| 백업 실패·오프라인 | 기록은 기기에 정상 저장된다. 올리지 못한 변경은 보관했다가 연결되면 올린다. 앱 설정에서 상태를 볼 수 있다 |
| 복원 충돌 | 기기와 서버 둘 다 기록이 있으면 사용자가 하나를 고른다. 사라질 쪽을 먼저 경고한다 (4.8) |
| 로그아웃 중 전송 실패 | 로그아웃을 멈추고 이유를 알린다. 올리지 못한 변경이 있는 상태에서 기기 데이터를 지우지 않는다 |
| 만 14세 미만 | 계정 연결을 막고 이 기기에서만 쓰도록 안내한다 |
| 오늘 칸이 이미 참 | 달력판에서 같은 날 중복 배치를 막고, 막힌 이유가 드러나야 한다 |
| 긴 목표 이름 | 목록 카드는 2줄까지 쓰고 넘치면 말줄임, 판 상세 제목은 전부 줄바꿈해 보여준다 (2026-09-29 Storybook 확정) |

## 8. 권한과 개인정보

- 사진 접근은 **기록에 사진을 첨부할 때만** 요청한다. 앱 최초 실행에서 미리 요청하지 않는다.
- iOS는 `NSPhotoLibraryUsageDescription` 등 사용 목적 문구가 없으면 심사에서 거절된다. 한국어로 용도를 밝힌 문구를 image-picker 플러그인 옵션 `photosPermission`으로 지정한다. 구현 현황은 [HANDOFF](HANDOFF.md) 9절을 따른다.
- 로그인하지 않은 사용자의 데이터는 기기에만 있고, 서버가 수집하지 않는다.
- 로그인하면 서버가 계정 식별자(Apple/Google), 이메일(Apple의 이메일 가리기 사용 시 중계 주소), 목표·스티커·메모, 리사이즈한 사진을 보관한다. 분석 도구를 넣을 경우 수집 항목을 이 절에 추가한다.

### 8.1 출시 전 준비할 약관·정책 (2026-09-28 점검)

법적 항목은 개인정보 보호법 기준의 정리다. **최종 문안은 법률 검토를 받는다.**

**2026-09-30 확정.** 약관·처리방침은 별도 공개 저장소 `chagok-app-policy`(GitHub Pages)에 판별로 게시한다. 게시일과 시행일을 따로 두고, 앱은 같은 URL을 앱 안 시트로 연다. 로그인한 사용자는 동의가 필요한 판이 시행되면 다음 실행 때 다시 동의한다. 로그인하지 않은 사용자에게는 동의를 받지 않는다. 설계: [약관 설계](superpowers/specs/2026-09-30-policy-terms-design.md).

## 9. 플랫폼 차이

- Android 하드웨어 뒤로가기에서 목표 생성·기록 화면이 올바르게 닫혀야 한다. 저장하지 않은 입력이 있으면 그대로 버리지 않는다.
- 햅틱은 기기와 설정에 따라 사용할 수 없다. 햅틱이 없어도 배치 성공이 시각적으로 전달돼야 한다.
- 사진 권한 요청 흐름과 문구가 두 플랫폼에서 다르다. 거부 후 재요청 가능 여부도 다르므로 설정 유도 문구를 각각 확인한다.
- 그 외 플랫폼별 UI 차이는 미확정이다.

## 10. 완료 기준

- [ ] 이름과 판 종류를 선택해 목표를 만들고 해당 판을 볼 수 있다.
- [ ] 홈에서 목표를 전환하고 이름·진행을 확인할 수 있다.
- [ ] 달력판에서 이전/다음 달로 이동할 수 있다. 버튼과 좌우 스와이프가 모두 동작한다.
- [ ] 달력판에 그 목표의 누적 총계가 월별 진행과 구분되어 표시된다.
- [ ] 월이 바뀐 직후에도 그전까지 쌓은 양을 화면에서 확인할 수 있다.
- [ ] 기본 스티커를 목표별로 설정하고 빈칸에서 재선택 없이 붙일 수 있다.
- [ ] 서로 다른 목표의 기본 스티커 설정이 독립적으로 유지된다.
- [ ] 기본 스티커 변경이 이미 배치한 스티커를 일괄 변경하지 않는다.
- [ ] 사진·메모 없이도 붙이기가 완료되고, 선택적으로 추가·편집할 수 있다.
- [ ] 붙인 스티커를 열고 다시 뗄 수 있다.
- [ ] 첫 실행 안내를 진행/건너뛰기 할 수 있고 불필요하게 반복하지 않는다.
- [ ] 앱을 다시 열면 저장한 목표·스티커·기록이 유지된다.
- [ ] 출시 단계에서 다른 기기 또는 재설치 후 계정으로 기록을 복원할 수 있다.
- [ ] 로그인 없이('나중에') 모든 기록 기능을 쓸 수 있고, 나중에 설정에서 계정을 연결할 수 있다.
- [ ] 기기와 서버에 모두 기록이 있을 때 사용자가 남길 쪽을 고르고, 사라질 쪽을 먼저 경고받는다.
- [ ] 로그아웃은 올리지 못한 변경을 모두 올린 뒤에만 기기 데이터를 지운다.
- [ ] 앱 안에서 계정을 삭제할 수 있고, 서버 데이터와 Apple 토큰이 함께 정리된다.
- [ ] 만 14세 미만은 계정 연결이 제한된다.
- [ ] 적립판의 어느 빈칸에든 붙일 수 있고, 중간 스티커를 떼도 다른 스티커가 움직이지 않는다.
- [ ] 판을 다 채우면 완성 표시가 나오고, 적립판은 새 목표 시작 / 칸 늘리기를 고를 수 있다.
- [ ] 목표를 삭제하면 확인 후 스티커·기록·사진까지 지워진다.
- [ ] 기록이 없는 스티커는 확인 없이 떼지고, 기록이 있으면 확인을 거친다.
- [ ] 이용약관·개인정보 처리방침·오픈소스 라이선스를 앱 안에서 볼 수 있다.
- [ ] 사진 권한을 거부해도 스티커 붙이기와 메모가 계속 동작한다.
- [ ] 저장에 실패하면 사용자가 알 수 있고 입력이 사라지지 않는다.
- [ ] 모든 탭 대상이 플랫폼 최소 터치 크기를 만족한다.
- [ ] 출시 전 iOS 사진 권한 사용 목적 문구가 `app.json`에 포함된다.
- [ ] 평가·통계·연속일수·보상·상시 하단 팔레트가 추가되지 않는다.

이 체크리스트는 수용 기준이며 현재 완료 현황이 아니다.

## 11. 현재 단계와 후속 결정

현재 단계는 **로컬 동작 MVP**다 (2026-09-28). Expo Router 화면 4개가 로컬 SQLite 저장소에 연결돼 있고,
디자인 시스템은 Storybook에서 시각 검토 중이다. 실기기 검수는 아직 하지 않았다.
4.7–4.9절과 8.1절은 이번에 정의했고 아직 구현하지 않았다. validation은 사용자의 요청에 따라 후속 보정으로 남긴다.

구현 현황과 남은 구현 과제는 이 문서에 따로 적지 않는다. [인계 문서](HANDOFF.md) 8·9절을 단일 출처로 삼는다.

**2026-09-29 Storybook을 앱 전환의 기준으로 확정했다.** 그 밖에 테스트 통과·토큰 버전·문서의 baseline 표기만으로 사용자 승인을 추정하지 않는다.
시안과의 픽셀 단위 일치도 아직 아니며, 폰트·프레임 치수·공통 focus·단색 asset에서 오는 차이가 남아 있다.

# 법령 검토

출시·업데이트할 때마다 약관·개인정보 처리방침이 기대는 법령이 바뀌지 않았는지, 그리고 문서가 지금 앱과 여전히 맞는지 확인한다.
[출시 전 최종 점검](RELEASE-CHECKLIST.md) 6절에서 이 문서를 따른다.

법률 자문이 아니다. 조문 원문 대조와 변경 감지까지만 하고, 해석이 갈리는 것은 「물어볼 곳」에 묻는다.

처음 만듦: 2026-10-14.

## 2. 출시·업데이트할 때마다

1. **바뀐 법령 찾기** — `execute_tool(tool_name="search_law_bulk")`에 1절 법령 이름을 넣는다. MST가 표와 다르거나 새 「시행예정」이 생긴 법령만 본다.
2. **바뀐 조문 보기** — 그 법령에서 「문서가 기대는 조문」을 `get_law_text`로 열어 지난 내용과 비교한다. 시행예정본은 `efYd`에 시행일을 넣는다. 고시는 `search_law`로 찾아 발령일을 비교한다.
3. **인용 확인** — 약관·처리방침 본문을 `legal_analysis(mode="verify_citations")`에 넣어 인용한 조문이 모두 실존하는지 본다.
4. **문서가 앱과 맞는지** — 아래를 하나씩 본다.
   - 이번 업데이트로 새로 받는 정보, 새 외부 회사(SDK), 새 유료 상품, 바뀐 가격·환불 방식이 처리방침·약관에 있다.
   - 처리방침의 수탁자·국외 이전 표가 지금 쓰는 서비스와 같다(Supabase, RevenueCat, AdMob 등).
   - 보관 기간 문장이 1절 시행령 6조 기간과 같다.
   - 약관의 청약철회·환불 문장이 앱 화면 안내(PRD 4.12 「사기 전 환불 안내」)와 같다.
   - 통신판매업 신고 면제 조건이 아직 맞는다(직전년도 거래 횟수, 간이과세자 여부).
5. **고칠 게 있으면** — 약관·처리방침 새 판을 만들고(정책 사이트 `versions.json`), 앱의 동의 판 번호를 올린다. 문서만 바뀌고 앱이 그대로면 그 사실만 적는다.
6. **기록** — 1절 표의 MST·시행일을 고치고 3절에 한 줄 남긴다.

## 4. 물어볼 곳

조문만으로 답이 안 나온 것(2026-10-14 기준). 2026-10-29 2차 검토에서 늘어난 쟁점은 5절 「변호사에게 물을 것」에 모았다:

- 새 계정 동의를 로그인 뒤에 받아서(2026-10-21), 만 14세 미만이 가입을 그만할 때까지 계정(Apple 사용자 ID와 이메일)이 잠깐 서버에 있다가 지워진다. 개인정보 보호법 22조의2는 「동의를 받아」 처리할 때 법정대리인 동의를 요구하는데, 동의 전 잠깐 생긴 계정이 여기에 걸리는지 — 해석 확인 필요
- 미성년자 결제: 만 14세 이상이지만 미성년인 사용자의 인앱 구매 취소권(민법 5조)을 약관에 어떻게 적을지 — 스토어 결제라 Apple과 Google 환불 절차와 함께 확인
- 앱 개발자가 인앱 판매에서 「통신판매업자」인지, Apple·Google이 「통신판매중개자」인지 — 해석례 없음
- 사업 첫해의 「직전년도 거래 횟수」를 어떻게 보는지

물어볼 곳: 관할 구청 통신판매업 담당(신고), 개인정보 포털 privacy.go.kr · 118(처리방침·보관), 대한법률구조공단 132(소득 기준 있음), K-Startup 무료 법률자문(지원사업 선정 기업).

## 5. 2차 검토 (2026-10-29)

법률 자문이 아니라 검토 보조 자료다. 조문은 법제처 원문(korean-law)에서 인용했고 실존을 다시 확인했다. 기준은 앱 `origin/main`(859e00e)과 정책 사이트 1판이다. 이용약관과 유료 상품, 개인정보 처리방침, App Store 심사 관점 세 보고서로 나눠 봤고, 원문은 운영자가 보관한다(공개 레포에 두지 않는다).

### 요약

1. 로그인하지 않고 사는 사람은 약관에 동의한 적이 없고, 결제 직전 확인 창에 약관, 청약철회 방법, 미성년자 취소 안내가 없었다. 확인 창의 「환불이 어려울 수 있어요」는 법이 요구하는 「철회가 불가능하다는 사실」보다 흐려 약관 11조 3항과도 맞지 않았다.
2. 통신판매업 신고를 면제받아도 주소와 전화번호 표시 의무(전자상거래법 13조 1항)는 남는다. 약관과 지원 페이지에 아직 없다.
3. 처리방침 보유 기간에 서버 로그 90일, 앱에서 지운 기록이 서버에 삭제 표식으로 남는 동작, 카카오 연결 해제 실패 기록이 빠졌다.
4. 운영 보안 항목 3건(서버 운영과 접근 관리) — 비공개 기록. 처리방침 11절(안전성 확보조치)과 맞추는 일이 남았다.
5. 심사 쪽 큰 위험은 Google 로그인 동의 화면 게시, 유료 앱 계약과 인앱 상품 첨부, 개인정보 라벨의 추적 칸, 스크린샷 08의 「무료」 배지다.

### 변호사에게 물을 것

1. 인앱 판매에서 앱 개발자가 「통신판매업자」인지, Apple이 중개자인지 판매 당사자인지. 전자상거래법 10조, 13조, 17조가 누구에게 걸리는지가 이 답에 달렸다
2. 로그인하지 않은 구매자에게 결제 확인 창의 약관 링크만으로 약관이 편입되는지(약관규제법 3조). Apple 표준 EULA와의 관계
3. 스티커 묶음(10종)이 「가분적 디지털콘텐츠」인지. 그렇다면 한 장을 고른 뒤에도 나머지는 철회 대상일 수 있다
4. 광고 제거가 디지털콘텐츠인지 용역인지, 결제 완료를 철회 불가 시점으로 둔 것이 허용되는지(시행령 21조의2 4호)

사용자가 시안을 보여달라고 하면 **Storybook 작업부터 하지 않고 아티팩트(HTML)로 먼저** 보여준다. 시안이 모두 확정되면 그때 Storybook 컴포넌트(`src/design-system/`, `stories/`)에 반영한다.

아티팩트 형식은 2026-10-01 약관 동의 시안(`terms-consent.html`)과 같게 한다:
- 안마다 한 띠: 배치 설명, 좋은 점/걸리는 점, **[이 안 고르기]** 버튼, **메모 칸**(안마다)
- 현재안이 있으면 비교용(고를 수 없음)으로 맨 위에 둔다
- 아래 고정 막대에 고른 안 요약 + **[메모까지 복사]**
- 고른 안·메모는 `db` capability로 저장해 Claude가 `ArtifactData`로 읽는다(안 되면 localStorage + 복사 안내)
- 시안 묶음이 여러 개면(예: 설정·아이콘·스플래시) 묶음마다 따로 고른다

**Why:** 2026-10-03 사용자 지시. 고르기 전에 Storybook 코드를 만들면 버릴 코드가 쌓이고, 아티팩트에서 바로 고르고 피드백을 남기는 쪽이 빨랐다.

**How to apply:** "시안 보여줘" → artifact-design·artifact-capabilities 스킬 로드 → 위 형식으로 발행 → 사용자가 고르고 메모를 남기면 `ArtifactData`로 읽는다 → 모두 확정된 뒤 Storybook에 반영. [[decision-options-format]]의 3안 제시와 함께 쓴다.

**앱 화면은 실제 컴포넌트로 (2026-10-06 추가).** 시안 속 앱 화면을 HTML로 흉내 내지 않는다. 실제 디자인 시스템 컴포넌트로 조합한 임시 스토리(`stories/_proposal/`, 커밋하지 않음)를 Storybook에서 렌더해 캡처하고(Chrome headless `--screenshot`, 390×844, 2배), 그 PNG를 아티팩트에 넣는다. 안은 **지금 화면 구조 안에서** 바꾸고, 디자인 시스템에 없는 요소는 새 요소라고 따로 밝힌다. 발행 전에 렌더한 캡처를 직접 본다.
**Why:** 2026-10-06 컬러 스티커 화면 시안 1판을 예전 광고 시안의 HTML 틀로 그렸다가, 사용자가 "현재 화면 프레임 구조나 버튼 디자인은 무시하고 그린거야?", "베리에이션 하더라도 지금 구조에서 베리에이션 하는게 맞을꺼 같은데?"라고 지적했다(머리글·배지·탭·포커스 링이 실제와 달랐다).

**기존 화면은 실제 화면 컴포넌트를 쓰고 대조한다 (2026-10-08 추가).** 기존 화면(새 목표·홈·판 등)을 시안에 넣을 때 조각을 손으로 다시 조립하지 말고, 실제 화면 컴포넌트(`NewGoalScreen` 등)나 같은 순서의 같은 컴포넌트를 쓴다. 발행 전에 실제 스토리(`screens-home-structure-…`)를 같이 캡처해 나란히 본다.
**Why:** 2026-10-08 「새 목표」 캡처에서 판 종류·칸 수가 빠져 있었고, 사용자가 "기존 화면 그대로 반영된거 맞아?"라고 물었다.
